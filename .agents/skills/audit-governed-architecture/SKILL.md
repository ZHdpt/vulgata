# Audit Governed Architecture

Use the enabled architecture-review adapter's complete Explore/report process for a transaction-safe epic gate. The supported adapter combines `$codebase-design` vocabulary with applicable `$bmad-review` lenses; never modify either upstream skill.

## Authorities and Boundary

Read the selected adapter under `.governed-delivery/adapters/architecture-review/` and its upstream skills completely. Also read the pinned epic/stories, `AGENTS.md`, Constitution, selected contexts, ADRs, canonical glossary, and `../run-governed-delivery/references/artifact-contracts.md`.

Operate only on the clean detached audit checkout and source identity supplied by `$close-governed-epic`. Remain read-only in every filesystem except the root-owned HTML file in OS temp. Do not select a candidate, enter the grilling loop, update context/ADRs, implement, disposition findings, change lifecycle state, stage, or commit.

## Process

1. Apply `codebase-design` module/interface/seam/locality criteria and the applicable `bmad-review` adversarial, edge-case, verification-gap, and structural lenses using a fresh direct-child `epic-architecture-auditor` as the independent Explore/classification judge. Preserve `agents.max_depth = 1`.
2. Bind the dispatch to the canonical audit root, Git common/worktree identities, full source commit, tree/index IDs, and hashes of every authoritative input.
3. Require `ACCEPT|REVISE|BLOCKED` plus every candidate with stable raw ID, strength, severity, all applicable categories, MUST/ADR relationships, and Git-verifiable byte-range citations.
4. Return the complete tool envelope unchanged to the root before normalization.
5. Have the root losslessly normalize the returned candidates. Generate any visible HTML cards deterministically from the normalized payload, write/open only a fresh OS-temp report, and retain its absolute path/hash.
6. Return candidate selection as explicit follow-up. `$close-governed-epic` either records category-valid dispositions or routes selected exploration and every side effect through BMad corrective work, then reruns this audit at the new commit.

## Completion Contract

Complete only when checkout/input proofs, raw response, candidate classifications, citations, normalized payload, visible report, hashes, and source identity satisfy the epic architecture evidence contract. A clean independent `ACCEPT` may advance without duplicate user approval. Reserved findings remain human-gated. Never weaken, merge, omit, or self-disposition a candidate.
