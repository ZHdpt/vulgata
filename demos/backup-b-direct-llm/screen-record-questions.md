- Repository：`mbs_account`、`mbs_channel`

当前对话检索边界聚焦于已确认的跨 Repository 会话更新关系：

真实提供方偶发不可用，因此正式录屏前仍应预热。

## 业务模式

### 首选问题（成功过，但不稳定）

`移动端渠道会话更新包含哪些主要步骤？`

预期展示：

- 移动端消费方设置渠道、机构和 SOFA 调用参数；
- 渠道提供方校验参数、保存客户信息并提交会话；
- 构造 Redis key、保存会话对象并设置 token 缓存；
- 回答包含“查看来源”控件。

该题曾在约 15 秒内成功，也曾返回 `当前知识证据不可用或已更新，请稍后重试。`。
正式录制前先试问；只有成功后再开始业务模式镜头。

### 备用问题（同一证据边界）

- `移动端消费方和渠道提供方在会话更新中各自负责什么？`
- `客户信息和会话令牌在跨仓库更新过程中如何被保存？`

备用问题应在正式录屏前各试问一次；提供方输出存在耗时与选句波动。

### 代码逻辑业务化备用问题

这些问题用于展示“没有对应业务逻辑文档时，仍可用非技术语言解释代码逻辑”的降级路径：

- `认证错误次数检查操作类负责什么？`
- `登录认证错误次数超过上限会怎样？`
- `登录密码校验失败后会怎样？`

回答仍引用原始代码逻辑文档和源码位置；模型改写只影响展示文字，不改变证据、哈希或引用。
如果知识库确实没有相关安全证据，会返回“当前知识库中没有足够信息回答该问题”。

## 录屏顺序

1. 录制前预热业务模式首选问题；成功后保留该镜头并展开一个来源。
2. 切换 IT 模式：首选问题，展示两个 Repository 的引用。
3. IT 模式：SOFA 参数问题，展示技术细节。
4. 展示不相关问题的即时拒答。
5. 可选：Redis/token 问题或代码逻辑业务化备用问题。

每题预留 30–45 秒；如果出现证据不可用、提供方错误或超时，不要在正式镜头中继续等待，
刷新页面后先用已验证首选问题预热一次。
