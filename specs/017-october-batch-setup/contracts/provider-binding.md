# October Host Provider Binding Contract

For the generator process, the operator explicitly declares one configuration source and precedence. The selected route is host-supplied configuration; there is no automatic `.env` path discovery. A later generator database configuration route requires explicit selection, implementation and, for copied protected rows, verified compatible Data Protection keys, application-isolation identity and protector purpose. Ordinary Web retains normal provider administration and does not load this document or invoke this binder at startup. No generator provider input is a Web startup prerequisite.

Each Worker and Chat role selects a named profile with a complete API type, endpoint, model and protected credential reference from the selected source. The roles may deliberately name the same profile; omission cannot silently collapse them. Validate one profile as a unit: no missing field is backfilled from another source or role, and no provider switch follows validation or runtime failure. Neither the model nor a tool call may choose a credential or endpoint.

The effective generator binding is fixed for its process lifetime. Changing its source, profile or selected batch requires restart. This does not freeze ordinary Web provider administration. Binding validation reports configuration identity/presence and sanitized failure class, without exposing key material or making a paid availability call. Provider readiness and generation quality require later separate evidence; a valid binding proves neither.

## Callable host-supplied binding

Pin the already selected host-supplied route through one concrete `Vulgata.Infrastructure.Configuration.OctoberProviderBinder`. Reuse `Vulgata.Core.DomainServices.ISecretEncryptionService` and the existing LlmApiKey purpose value `Vulgata.LlmProviders.ApiKey`, canonically named by `Vulgata.Shared.SecretPurposes.LlmApiKey`. Infrastructure currently references Core only; using this fixed existing purpose value does not add a Shared/Web reference or move the encryption implementation. No new protection scheme, credential resolver, provider adapter or database-loading route is introduced.

```csharp
public sealed class OctoberProviderBinder
{
    public OctoberProviderBinder(ISecretEncryptionService encryption);
    public Task<OctoberProviderBindingResult> BindAsync(
        OctoberProviderConfiguration configuration,
        CancellationToken cancellationToken = default);
}
public sealed record OctoberProviderProfile(
    string Name, ApiType ApiType, string Endpoint, string Model,
    string CredentialReference);
public enum OctoberProviderBindingStatus
{
    Bound, InvalidConfiguration, CredentialUnavailable, Cancelled
}
public sealed record OctoberProviderBindingResult(
    OctoberProviderBindingStatus Status, OctoberBoundProviderConfiguration? Binding);
```

`ApiType` is the existing Core enum; each role profile chooses exactly one of ChatCompletions, Responses or Messages, not None, a bitwise combination or an unknown value. Supporting configuration vocabulary does not claim that a provider transport is qualified.

`OctoberProviderConfiguration` is a sealed immutable class with constructor `(string sourceIdentity, string precedence, string workerProfile, string chatProfile, IReadOnlyCollection<OctoberProviderProfile> profiles, IReadOnlyDictionary<string, string> protectedCredentials)`. It exposes read-only SourceIdentity, Precedence, WorkerProfile and ChatProfile strings, Profiles as ImmutableArray<OctoberProviderProfile> and ProtectedCredentials as ImmutableDictionary<string, string>, defensively copied with ordinal keys. The dictionary maps exact opaque credential references to protected ciphertext from that same source, never to plaintext or a path for implicit loading. It is host input, not a model/request DTO or durable October record. Its diagnostic representation is the type name only; ciphertext, credential references and arbitrary input are never interpolated into failure diagnostics. OctoberProviderProfile likewise suppresses its generated diagnostic representation. Null constructor dependencies/collections throw ArgumentNullException; invalid configuration values are represented for BindAsync to reject with its closed result. A null BindAsync configuration is programmer misuse and throws ArgumentNullException.

`OctoberBoundProviderConfiguration` is a sealed immutable result with an internal construction path and read-only SourceIdentity/Precedence strings and Worker/Chat properties of type OctoberProviderProfile. It contains only the two validated profile selections and protected credential references, no decrypted key or unvalidated profile collection. Its diagnostic representation is the type name only. Only Bound carries a nonnull Binding; all other statuses have null Binding and expose no partially valid role. This result establishes configuration validity, not a runnable Worker or Chat client.

Generator invokes the existing binder once after final configuration is fixed and before ExecuteAsync. A binding failure stops generator startup with sanitized nonzero/failure classification before setup migration or data access; no partial Worker-only startup. Generator owns the immutable input snapshot and successful result for that process; the binder borrows the encryption service and disposes neither it nor host configuration. Reload does not invoke the binder or replace selected profiles. Remove Web's former October provider loader/invocation/retained result with the special selected-data path; preserve ordinary ISecretEncryptionService and provider administration consumers.

For this route, one explicit `October:Providers:ConfigurationFile` names a host-supplied UTF-8 JSON document, read once without reload. No default path or .env search exists. The complete document supplies `sourceIdentity`, `precedence` (exactly `only-source`), `workerProfile`, `chatProfile`, `profiles` (objects with `name`, `apiType`, `endpoint`, `model`, `credentialReference`) and `protectedCredentials` (reference-to-ciphertext object). JSON apiType names are exactly `chat-completions`, `responses` or `messages`, mapped to the enum above. The host validates duplicate/unknown JSON properties, duplicate profile names/references, types and required fields before construction; malformed/unreadable input is a sanitized configuration failure. Profiles and ciphertext are taken only from that complete document, not the flattened combination of environment, command-line, ordinary provider registry or another file. The explicit file selector may be supplied through normal host configuration, but two distinct supplied selector values or competing October provider-source inputs are rejected rather than silently overriding. This pins selection mechanics permitted by spec Assumptions; it does not provision a file, key ring or secret and does not authorize accessing any actual resource.

BindAsync first checks cancellation and validates the complete selected roles/profiles/reference map before decrypting anything. SourceIdentity, both role names, selected profile names/model and credential references must be nonblank exact strings; names/references use ordinal matching, with no whitespace normalization or aliases. Precedence must be exactly only-source, and duplicate profile names deny even for direct typed callers. Endpoint must be an absolute HTTP(S) URI without userinfo or fragment; it is never contacted during binding. Both selected profiles must exist and be complete, with nonempty protected entries in the same document. Naming the same profile for both roles is deliberate sharing; an absent role never inherits the other. A missing selected value is never borrowed. Unselected profiles and unused protected entries confer no effective binding and are not decrypted.

For each distinct credential referenced by a selected role, call the existing `DecryptAsync("Vulgata.LlmProviders.ApiKey", ciphertext, cancellationToken)`, await completion, then require nonblank plaintext and immediately release that temporary reference. This is the unchanged canonical purpose, never an input-selected string. Do not retain or return decrypted material; immutable framework strings cannot be claimed securely zeroed. Existing Data Protection keys/application identity/purpose determine compatibility; exceptions or empty decryption return CredentialUnavailable without exception text. Check cancellation before/after each awaited call because the current encryption implementation may complete synchronously without observing its token. Caller cancellation returns Cancelled with no binding. No automatic retry, key discovery, encrypted-row copy, provider client, availability probe or paid call occurs.

Tests construct the same binder and immutable input, using controlled encryption for closed failure/cancellation outcomes and the existing real encryption service with test-owned ephemeral Data Protection for compatibility evidence. Assert complete distinct/deliberately shared profiles, missing/conflicting input, atomic failure, no cross-source backfill, no decrypted result/diagnostic and immutable selection. Retain actual generator document loading/invocation tests, including rejection before side effects; a binder-only test does not prove executable wiring. Ordinary Web tests prove startup without October provider input and no invocation of this route, while normal provider administration remains. Classify verification by changed behavior: changed startup uses behavioral RED/GREEN, already correct binder/protection behavior uses regression, and removing unused code uses appropriate direct/regression checks. Do not repeat declaration scaffolding or fabricate RED for completed behavior.
