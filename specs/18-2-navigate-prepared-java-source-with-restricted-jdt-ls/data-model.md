# Navigation Data and Lifetime Model

Navigation records bind to integrated Story 18.1 source identity and authorization without changing its public read issuer, context, functions or result envelope. Story 18.2 owns the shared trusted physical-workspace lease; Story 18.3 consumes it after a separately authorized verified checkpoint.

| Concept | Required information | Invariant and owner |
| --- | --- | --- |
| Prepared source approval | Existing `PreparedSourceApproval`: batch, Repository, subject, `WorkerSourceRead` purpose, approval/root-binding identities, operator label | Owned by 18.1. Exact current tuple is checked at issuance, during use and before disclosure; no Worker argument selects it. |
| Tool purpose authorization | Trusted application-selected `JdtNavigation` or `CodeGraphPreparation` with current authorization | Owned by shared 18.2 seam. `WorkerSourceRead` alone is insufficient for a subprocess/tool. |
| Trusted workspace lease | Prepared approval, selected tool purpose, held root identity/handle, deadline, cancellation and lifetime | Infrastructure-only physical path access; asynchronous disposal after all adapter calls. JDT-independent for 18.3. A path lease is not subprocess containment. |
| Contained root callback scope | Expected tool purpose, short-lived internal root binding, state-root separation check and raw `file:` URI to `PreparedSourceLocation` mapping | `UseContainedRootAsync` checks exact current authority/root identity before and after a bounded callback, serializes with disposal and returns only check status. Scope/physical path cannot escape to Agent/model; lease retains handle/identity. |
| Navigation profile | Trusted disposable state root, initialization/request/shutdown timeouts and response-byte cap; restricted no-import/no-build/no-restore settings | Application-built; contains no physical source root or executable selector. State root must be separate from prepared source. Real runtime resolves trusted host PATH commands separately. |
| Navigation factory/open result | Fixed profile, trusted injected JDT runtime, caller-held `JdtNavigation` lease; `Opened`, sanitized failure or `CleanupUnconfirmed` with nullable context; one-session slot | October Infrastructure seam, not legacy `AnalysisScope`. Exactly one context on `Opened`, none otherwise. Factory releases slot only after confirmed cleanup, quarantines it on unconfirmed cleanup, and disposes a returned session if later handoff fails; caller owns lease disposal on every path. |
| JDT runtime session | Injected process/protocol behavior, raw URI/range replies, process/protocol/disposable state | Runtime owns every partial resource until successful session return and cleans on pre-return exception/cancellation. Returned session passes to factory until context handoff, then context owns it. Controlled fake exercises lifecycle without real launch; production runtime remains unavailable until accepted PATH/process-profile work. |
| Runtime command binding | Trusted ordered host `PATH` resolution of exact JDT-LS/Java names; pinned absolute command path, file identity and digest | Production runtime rejects untrusted first matches, prepared/tool-state/current-directory entries, reparse or replacement and unsupported types before launch. Command identity lasts one session. No model override or `.env` selector. Command invisibility that blocks qualification is paused and reported. |
| Navigation request | Definition or references; granted Repository-relative Java path; one-based source position; bounded result controls | Must validate against live grant before protocol use. No absolute/traversing/symlink-escaping input. |
| Navigation session | Trusted lease/profile binding; owned process/protocol; separate disposable data/configuration; queue and health state | At most one live session per selected Repository. No cross-binding reuse; cleanup affects owned resources only. |
| Navigation observation | Request kind; observed contained relative path/range locations; observed count/limit state; capability/classpath limitations | A location is evidence only within the live grant. No raw physical URI or source content to Worker. |
| Navigation outcome | Observations plus explicit `observed`, `no result observed`, `limited`, `denied`, `authority unavailable`, `failed`, `cancelled` or `timed out` meaning | Zero locations never proves absence. Authority loss discards all buffered locations/counts/limits across concurrent calls; an unmappable URI is withheld. |

## State transitions

```text
not acquired -> acquiring -> initializing -> ready -> settling -> released
                      |              |         |
                      +----failed-----+--unhealthy/timeout
```

One bounded queue serializes protocol work when concurrent calls are unsafe. Factory open checks the current JDT-purpose lease and reserves one session slot before starting the injected runtime. Before a session is returned, the runtime settles any partial process/protocol/state on exception/cancellation; the factory maps sanitized status and releases its slot only with confirmed cleanup. Unconfirmed cleanup yields `CleanupUnconfirmed`/null context, leaves the slot unavailable and makes another open return immediately without invoking runtime; a Worker sees only empty `ConfigurationUnavailable`. After a session is returned, the factory disposes it if later validation/context creation fails; after successful context handoff, context disposal settles that session and releases the slot. The caller disposes its separate borrowed lease afterward, or directly after failed open. A waiting cancellation removes that request; active cancellation/timeout retires the session if protocol settlement cannot be established. Revoked/changed/unavailable authority latches the lease and session closed, cancels owned activity and discards pending outputs. A subsequent attempt requires new issuance under current source and tool-purpose authority; it never reopens a closed lease. This state is disposable, not Knowledge or a durable Source Snapshot.

## Containment and currentness

Validate relative inputs and every returned URI against the live, application-granted prepared root, including symlink/reparse escapes. The internal root scope uses the held root handle for no-follow containment and rejects state-root overlap or reparse redirection. It is invalid after callback completion; only contained relative locations may be retained. Never return a location that cannot be mapped safely. Recheck exact current source and tool-purpose authority immediately before release of any response; changed authority/root discards buffered mappings. The operator keeps source unchanged; known absence/change invalidates inspection claims. No repository-wide hash/change detector is introduced. Separate JDT-LS data/configuration from source, and qualify no source writes and actual subprocess confinement in the declared host profile. A root callback is not process containment.
