# Navigation Data and Lifetime Model

Navigation records bind to integrated Story 18.1 source identity and authorization without changing its public read issuer, context, functions or result envelope. Story 18.2 owns the shared trusted physical-workspace lease; Story 18.3 consumes it after a separately authorized verified checkpoint.

| Concept | Required information | Invariant and owner |
| --- | --- | --- |
| Prepared source approval | Existing `PreparedSourceApproval`: batch, Repository, subject, `WorkerSourceRead` purpose, approval/root-binding identities, operator label | Owned by 18.1. Exact current tuple is checked at issuance, during use and before disclosure; no Worker argument selects it. |
| Tool purpose authorization | Trusted application-selected `JdtNavigation` or `CodeGraphPreparation` with current authorization | Owned by shared 18.2 seam. `WorkerSourceRead` alone is insufficient for a subprocess/tool. |
| Trusted workspace lease | Prepared approval, selected tool purpose, held root handle/stable object identity (volume/file index), deadline, cancellation and lifetime | Infrastructure-only physical path access; asynchronous disposal after all adapter calls. The same stable root replacement check applies to JDT and CodeGraph leases because `.codegraph` creation changes parent last-write metadata. This does not change ordinary 18.1 reader semantics or prove source bytes unchanged. A path lease is not subprocess containment. |
| Contained root callback scope | Expected tool purpose, short-lived internal root binding, separate JDT state-root check and raw protocol-string `file:` location mapping | `UseContainedRootAsync` checks exact current authority/root identity before and after a bounded callback, serializes with disposal and returns only check status. The raw JSON-decoded string is screened before `System.Uri` normalization, then mapped using no-follow traversal. Scope/physical path cannot escape to Agent/model; lease retains handle/identity. |
| Dedicated CodeGraph workspace owner | `OwnershipId`, version, phase, exact application-held `PreparedSourceApproval`, canonical prepared-root path/stable object identity, workspace-owner identity and nullable physical entry identity; fixed `.codegraph` name is coordinator-owned | Trusted composition supplies an `Absent` draft; the 18.2 coordinator's durable versioned store commits `Creating` before create, `Ready` with observed non-null identity before use, `Disposing` before removal and `Removed` after checked absence, or `Quarantined` on uncertainty. ## State transitions

```text
not acquired -> acquiring -> initializing -> ready -> settling -> released
                      |              |         |
                      +----failed-----+--unhealthy/timeout
```

One bounded queue serializes protocol work when concurrent calls are unsafe. Factory open checks the current JDT-purpose lease and reserves one session slot before starting the injected runtime. Before a session is returned, the runtime settles any partial process/protocol/state on exception/cancellation; the factory maps sanitized status and releases its slot only with confirmed cleanup. Unconfirmed cleanup yields `CleanupUnconfirmed`/null context, leaves the slot unavailable and makes another open return immediately without invoking runtime; a Worker sees only empty `ConfigurationUnavailable`. After a session is returned, the factory disposes it if later validation/context creation fails; after successful context handoff, context disposal settles that session and releases the slot. The caller disposes its separate borrowed lease afterward, or directly after failed open. A waiting cancellation removes that request; active cancellation/timeout retires the session if protocol settlement cannot be established. Revoked/changed/unavailable authority latches the lease and session closed, cancels owned activity and discards pending outputs. A subsequent attempt requires new issuance under current source and tool-purpose authority; it never reopens a closed lease. This state is disposable, not Knowledge or a durable Source Snapshot.

CodeGraph ownership follows one compare-and-set lifetime: `Absent` draft → durable `Creating` → exclusive entry create/observed identity → durable `Ready` with non-null identity → durable `Disposing` before deletion → verified absence and durable `Removed`, or `Quarantined`. The store returns a new version only after atomic persistence. A competing/preexisting entry, changed identity, lost record, failed/unknown commit, revoked/unavailable exact authority, active child or uncertain cleanup cannot produce a verified `Ready` view; `Creating` or `Disposing` on restart remains unavailable pending owner resolution. A revoked tool lease cannot authorize cleanup. Trusted disposition supplies the currently selected approval, matching the durable record; injected existing source-current/tool-purpose and owner/readiness verifiers check the fixed `CodeGraphPreparation` purpose and root/entry identity before each bounded deletion chunk, then root/entry absence before a `Removed` commit/readback. Story 18.3 owns native child and ordinary reader repairs; neither is qualified by this record contract.

## Containment and currentness

Validate relative inputs and every JSON-decoded raw returned URI string against the live, application-granted prepared root, including literal device prefixes and symlink/reparse escapes. Reject unsafe raw syntax before URI parsing; the internal root scope uses the held root handle for no-follow containment and rejects JDT state-root overlap or reparse redirection. It is invalid after callback completion; only contained relative locations may be retained. Never return a location that cannot be mapped safely. Recheck exact current source and tool-purpose authority immediately before release of any response; changed authority/root discards buffered mappings. The operator keeps source unchanged; known absence/change invalidates inspection claims. No repository-wide hash/change detector is introduced. Separate JDT-LS data/configuration from source, and qualify no source writes and actual subprocess confinement in the declared host profile. The `.codegraph` exception is limited to one positively owned tool-state entry in a dedicated workspace. Neither callback nor state path is native child confinement.
