# Implementation Plan: Navigate Prepared Java Source with Restricted JDT-LS

**Branch**: `codex/18-2-plan` | **Date**: 2026-09-29 | **Spec**: [spec.md](spec.md)

**Input**: Story 18.2 of `docs/bmad/planning-artifacts/october-release-epics.md`, the September 26 October proposal, this feature's specification, the integrated Story 18.1 contract at `specs/016-contained-source-tools/contracts/prepared-source-tools.md`, and the user's dedicated in-place CodeGraph policy. Earlier plan-review-01–08 and definition-review-01–06 remain in history but do not accept this changed scope; repeat affected gates.

## Summary

Offer bounded definition and reference navigation through an application-bound JDT-LS tool over one whole operator-prepared Java Repository. Preserve Story 18.1's `PreparedSourceContextIssuer` and `IPreparedSourceReadContext` unchanged: they provide only list/read/search and do not expose a physical root. Story 18.2 owns the shared trusted physical-workspace lease. Its separate `CodeGraphPreparation` purpose can establish exactly one application-owned `.codegraph` entry inside an explicitly dedicated Vulgata-managed prepared workspace; application-controlled operations grant no other in-root write. Story 18.3 owns CodeGraph adapter/index/session use and ordinary-reader traversal repair. The user's narrow exception permits its pinned trusted CodeGraph child to run directly with inherited host filesystem rights, so the lease does not prevent native writes elsewhere; Story 18.3 must observe the actual footprint and block readiness on out-of-`.codegraph` writes or source/configuration/hook changes. Keep JDT-LS state separate from source and its distinct restricted process profile; disable automatic Maven/Gradle import, build and dependency restoration. Validate raw JDT protocol URI strings before `System.Uri` normalization and return only contained Repository-relative observations with truthful limits after a fresh pre-disclosure check. Qualify real navigation and JDT source no-write/process restrictions separately from CodeGraph's observed native effects.

This is a material agent-tool and shared authority change under `AGENTS.md`: fresh independent plan review and planned-change authorization precede corrected tasks. The user's in-place CodeGraph choice sets direction but is not approval of this exact plan. Subsequent delivery depends on accepted review, a separately authorized shared-workspace checkpoint for 18.3 consumption, and ordinary downstream gates.

## Technical Context

**Language/Version**: .NET 10/C#; JDT-LS and Java commands assumed available on the host `PATH`, subject to later runtime/profile qualification. Command visibility does not establish Java version, navigation or restricted behavior.

**Primary Dependencies**: Integrated 18.1 `PreparedSourceApproval`, `IPreparedSourceCurrentAuthorityVerifier`, `PreparedSourceContextIssuer`, `IPreparedSourceReadContext` and `PreparedSourceLocation` semantics; existing Infrastructure StreamJsonRpc/JDT-LS mechanisms. The shared trusted workspace seam is Story 18.2-owned and separately released to Story 18.3 after a verified checkpoint. Trusted Infrastructure resolves the JDT-LS and Java commands from the host `PATH`; neither config-file executable selection nor test-local `.env`/`JDT_LS_BIN` is required.

**Storage**: Disposable JDT-LS data/configuration remain separate from prepared source. In the dedicated Vulgata-managed workspace only, a `CodeGraphPreparation` lease may establish and operate one application-owned `.codegraph` entry; its ownership record and physical identity must survive individual lease disposal until workspace disposition. The lease itself is process-local. No database, Knowledge schema, source copy, Source Snapshot, Git revision identity or repository-wide hash is introduced here.

**Testing**: Honest behavioral RED/GREEN in `tests/Vulgata.Tests`, controlled seam tests, then real JDT-LS definition/reference and subprocess qualification under the accepted implementation route.

**Target Platform**: October host-run profile; generic Docker deployment target remains outside this October delivery slice. The Windows restricted-child candidate and host executable/permission prerequisites below are unqualified and confer no launch permission.

**Project Type**: Internal Worker tool and Infrastructure adapter in the existing modular monolith.

**Performance Goals**: Bounded readiness/request/queue/shutdown, one owned session per selected Repository, serialized unsafe protocol work. No completeness or throughput promise.

**Constraints**: Prepared source files and unrelated entries remain unchanged. Application-controlled CodeGraph preparation may write only its positively owned `.codegraph` subtree; ordinary model-visible Worker tools retain relative read limits and no arbitrary path/write/command capability. The pinned native CodeGraph child inherits host rights under the user's narrow exception, so this plan claims no preventive OS filesystem or network denial for that child; observed out-of-footprint writes or changed source/configuration/hooks block its readiness. JDT-LS keeps separate state and restricted process requirements. No source copy, dependency restoration or silent result truncation. Required native CodeGraph integration remains Story 18.3-owned.

**Scale/Scope**: One whole Java Repository per grant, with concurrent Workers sharing at most one owned session. No other LSP or multi-session policy.

## Implementation Design

### Responsibilities

- **ID-R01**: Trusted application composition selects the exact `PreparedSourceApproval` tuple (batch, Repository, subject, `WorkerSourceRead` purpose, approval/root-binding identities, operator label), physical root and JDT-LS profile. An additional application-selected tool purpose must authorize navigation; `WorkerSourceRead` alone is not unrestricted tool permission. Infrastructure owns workspace/process authority; Agent functions receive no physical root. This follows integrated 18.1, O-AR02/O-NFR01 and Constitution I/V.
- **ID-R02**: The navigation module translates requests and JDT-LS replies to bounded Repository-relative observations and limitations. It does not create source identity, accept Knowledge, infer a missing relationship from no result, own 18.1 file tools or replace CodeGraph (O-FR04–O-FR06; PRD FR-4.9/15.2).

### Interfaces

- **ID-I01**: One Worker-facing `PreparedJavaNavigationFunctions` construction surface borrows an issued navigation context and creates only definition/reference functions. Calls accept canonical Repository-relative Java path, one-based position and bounded result controls; return `repositoryId` and sanitized navigation outcome. Neither calls nor constructor can issue/change grants, choose a physical root, adapter or executable. The trusted caller owns async disposal after calls settle; cancellation is per call. See `contracts/navigation-tool.md` for callable shape. Preserve 18.1's three-function `PreparedSourceFunctions.Create()` exactly.
- **ID-I02**: Return observed relative path/range locations, request kind, explicit result bound/limit status and capability/classpath/failure classification. Zero locations mean `no result observed`, never absence proof. A capped LSP response is limited without an implied continuation. Withhold outside-grant URIs, physical paths and source content.
- **ID-I03**: Keep JDT-LS stdio, command resolution and the fixed restricted profile behind Infrastructure. Explicitly walk the host `PATH` entries in order for only `jdtls.exe`/`jdtls.bat` and `java.exe`; do not invoke a bare command or Windows ambient executable search. Treat empty/relative/current-directory entries or two supported JDT names in the same first matching entry as invalid resolution, not fallback lookup roots. Reject the first matching candidate if its canonical directory or any reparse-point ancestor lies in or can redirect into prepared source, disposable tool state, an unintended current directory or another host-untrusted entry; do not skip it for a later candidate. Require a regular non-reparse file of the expected extension under a host-approved executable directory protected from Worker/tool writes. Open and pin canonical path, file identity and content digest for the session, hold protection against replacement where supported, recheck identity immediately before absolute-path launch, and fail closed on mismatch. The approved process profile also governs any fixed `cmd.exe` interpreter and its children when the selected JDT command is a batch file; child `PATH` is constrained to approved resolved tools/system inputs. No model-selected command, config-file executable override, user-profile fallback or `.env`/`JDT_LS_BIN` discovery. If either command is invisible in the running host (including a stale process environment after a recent `PATH` edit) and blocks qualification, pause and report; do not guess another path. Resolved visibility is not runtime qualification. Models cannot select adapter, executable, workspace, import/build mode or host path (PRD FR-15.1/15.3; AD-15).
- **ID-I04**: Story 18.2 supplies `PreparedToolWorkspaceIssuer` in Infrastructure with a mandatory current-authority/tool-purpose verifier and `IssueAsync` taking trusted application-held grant/root, selected tool purpose and cancellation; it returns a status plus nullable process-local lease. The lease exposes lifetime/Repository ID to trusted composition and its physical root only to Infrastructure adapters, with bounded `CheckCurrentAsync` and `IAsyncDisposable`. For both JDT and CodeGraph purposes, pin stable root object identity (volume/file index) rather than mutable parent-directory last-write time; in-place `.codegraph` entry creation must not close a still-current JDT lease. This still rejects root replacement, while source-file unchanged claims require separate protected process and per-file evidence. A missing verifier, unauthorized purpose or unmatched tuple fails closed. Story 18.3 consumes this JDT-independent seam after its separately authorized verified checkpoint; exact shape is in `contracts/navigation-tool.md`.
- **ID-I05**: Keep the October `PreparedJavaNavigationContextFactory` constructor with fixed `PreparedJavaNavigationProfile` and injected public `IPreparedJdtLsRuntime`; its `OpenAsync(PreparedToolWorkspaceLease, CancellationToken)` accepts only a current `JdtNavigation` lease, returns exactly one context on `Opened` and null otherwise, and never accepts `AnalysisScope`, a model path, adapter name or executable. Add one internal October production runtime implementing the unchanged `IPreparedJdtLsRuntime.OpenAsync(lease, profile, token)`. Its trusted constructor takes an ordered-PATH resolver, an OS-enforcing process launcher and a stdio/protocol factory plus fixed host executable/profile policy; the internal typed resolution, launch and initialization requests/results are specified in `contracts/navigation-tool.md`. The runtime obtains the whole granted root from the short held-root callback, checks separate disposable state, resolves and pins the first JDT/Java candidates, rechecks current lease/root and pinned commands immediately before launch, then passes fixed `rootUri`, `workspaceFolders` and no-import/no-build/no-restore settings to protocol initialization. It returns an `IPreparedJdtLsSession` only after confirmed initialization; pre-return failure reports sanitized status and cleanup confirmation through `PreparedJdtLsOpenFailureException`. Controlled tests instantiate this actual runtime with recording internal dependencies; production composition remains closed until T022/T023 process-boundary work is accepted. No historical `AnalysisScope` factory is wrapped.
- **ID-I06**: Preserve the existing `internal` Infrastructure-only `PreparedToolWorkspaceLease.UseContainedRootAsync(expectedPurpose, callback, cancellationToken)` operation and its `PreparedToolWorkspaceCheckStatus` result. Its short-lived `PreparedToolRootScope` supplies trusted physical binding and separate JDT state-root validation. The raw protocol-string mapper takes JSON-decoded text before URI normalization, rejects device/extended-length/UNC, query/fragment, encoded path syntax and noncanonical file forms, then uses held-root-relative no-follow traversal to yield only `PreparedSourceLocation`. For JDT request admission and returned locations, the navigation context also consumes the **same** `PreparedCodeGraphStateCoordinator.GetOwnershipViewAsync` with the exact application-held workspace binding and current approval supplied by trusted Infrastructure composition, never by Worker arguments. A current `VerifiedOwned` Ready record with non-null entry identity authorizes exclusion only of paths whose held-root first entry is that recorded object; `VerifiedUnowned` permits legitimate same-name source, and `Unavailable` denies protocol use and payload. No new shared ownership view, descriptor, lexical name-only exclusion, public root/path/handle or 18.1 reader change is introduced. The lease operation checks exact live approval, JDT purpose, deadline and pinned root identity before and after a bounded callback; see `contracts/navigation-tool.md`.
- **ID-I08**: Add a trusted Web application composition seam, `PreparedJavaWorkerToolComposer`, whose constructor accepts the existing workspace issuer and October navigation factory as optional navigation services, and whose `ComposeAsync(alreadyIssuedSourceContext, applicationHeldSourceGrant, applicationSelectedJdtGrant, cancellationToken)` returns one disposable `PreparedJavaWorkerToolComposition`. Its result always contains the three independently created 18.1 file functions for a valid source context and contains the two navigation functions only after a successful JDT-purpose issue/open. A sanitized navigation status distinguishes open, denied, unavailable, cancelled and deadline outcomes without disclosing grant/root/profile. The composer requires the source/JDT grants' exact approval tuple and physical root to match, the grant purpose to be `JdtNavigation`, and the read context's Repository ID to match. The trusted caller must have issued that borrowed context from the supplied source grant; 18.1 intentionally exposes no full tuple with which the composer could prove this itself. `Program.cs` registers this seam with a closed navigation configuration until current source/tool authorizers, fixed profile and a controlled or later qualified runtime are explicitly supplied. Tests replace those trusted registrations with controlled doubles and call the same Web seam. The Worker cannot construct a grant, choose a runtime/profile/command or see the physical root. See `contracts/navigation-tool.md`.
- **ID-I07**: Add a separate internal `CodeGraphPreparation`-only owned-state operation on the shared lease, not a general write flag or extension of `IsSeparateDisposableStateRoot`. Trusted application composition supplies an `Absent` draft for exactly one dedicated workspace, and the 18.2-owned coordinator injects one durable, versioned ownership store. The coordinator commits `Creating` before any root mutation, exclusively creates `.codegraph`, observes its physical identity, and commits a non-null `Ready` record before exposing a state scope. `GetOwnershipViewAsync` reloads that same typed record, checks current source/owner authority and root/entry identities, and supplies the one positive binding to later leases, 18.3's ordinary reader and 18.2's JDT request/location eligibility. The JDT consumer checks ownership classification, not `CodeGraphPreparation` use authority; actual CodeGraph mutation separately requires that current tool purpose. No second descriptor or name-only filtering exists. Creation/commit uncertainty quarantines. For disposal, the coordinator injects existing `IPreparedSourceCurrentAuthorityVerifier` and `IPreparedToolUseAuthorizer`, accepts a trusted current `PreparedSourceApproval`, commits `Disposing` before deletion, checks exact source/CodeGraph/owner/readiness/root/entry state during bounded cleanup, and commits/readbacks `Removed` only after post-check; it never borrows a revoked lease. No Worker/Agent argument can name a state entry or receive its path. Native returned excerpt verification may reuse 18.1's bounded held-root-relative `ReadTextRangeAsync` under the same exact grant after 18.3's reader repair is qualified. See `contracts/navigation-tool.md` for exact callable transitions.

### State and Lifetime

- **ID-S01**: Key session ownership by the selected Repository binding from F0; permit at most one live JDT-LS process per selected Repository in the host. Root/profile conflict cannot reuse it. Acquisition and release include protocol, queue, process and disposable data/configuration; waits or busy results are bounded.
- **ID-S02**: Use the prepared Repository as the exact whole-source `rootUri`/`workspaceFolders` project root with separate disposable JDT-LS `-data` and configuration. The restricted child profile's redirected `TEMP`, `TMP` and application-profile data, if it uses them, are also owned disposable JDT state and must be observed, bounded and settled; an unexplained writable location fails the profile. Do not mirror/copy source, invent Git identity or use `PreparedRevisionJdtLsWorkspaceLeaseProvider` as an October grant. Qualification must establish no writes to prepared source; a failure returns for reviewed design correction.
- **ID-S03**: Each trusted lease binds the exact approval tuple, one selected tool purpose and stable observed root object identity. JDT-LS may retain its `JdtNavigation` lease for one bounded session while a separately authorized CodeGraph-purpose lease creates its owned state; the expected parent-directory metadata change is not root replacement. The purposes never share a lease or permission. Either closes on revoked/mismatched/unavailable authority, root object replacement, deadline, cancellation or disposal, cancels owned work and is never cached/reopened under restored approval. This object-identity rule does not weaken 18.1's ordinary reader `ChangedInput` semantics or prove source-file bytes unchanged. Process termination and tool-state cleanup remain adapter-owned; the shared issuer adds no JDT dependency for 18.3.
- **ID-S04**: Ownership changes only at a successful return from injected `IPreparedJdtLsRuntime.OpenAsync`: until then the runtime owns and settles every process, protocol and disposable-state resource it acquires, including on exception/cancellation before return. The factory owns the one-session slot, maps failed/cancelled open to sanitized null-context status and releases that slot only after runtime settlement is confirmed; it cannot dispose runtime partials it never received. A trusted `PreparedJdtLsOpenFailureException` with `CleanupConfirmed=false`, or an unexpected exception with no cleanup attestation, maps to `PreparedJavaNavigationOpenStatus.CleanupUnconfirmed` with null context, quarantines the Repository slot and blocks further runtime open/retry until owned-resource resolution. If surfaced to a Worker, map to existing `ConfigurationUnavailable` with empty payload. If a session is returned but later lease/profile validation, cancellation or context construction fails, the factory disposes that returned session before releasing the slot. After successful context handoff, the context owns/disposes the returned session and releases the slot after Worker calls settle. The context borrows the separately issued workspace lease; the trusted caller always disposes the lease after the context, or after failed open. No failed/disposed context or partial session is reusable.
- **ID-S07**: The Web composition result borrows the 18.1 read context and never disposes or replaces it. On navigation issue/open failure, it disposes any issued lease before returning the three file functions and no navigation functions; a null factory/issuer is `ConfigurationUnavailable` without an issue/open attempt. After `Opened`, it owns the navigation context then the lease, disposes both in that order after all Worker calls settle, and preserves lease disposal even if context disposal throws. Cancellation before handoff yields file-only `Cancelled` after owned resources settle; cancellation during Worker calls follows the existing context/function cancellation rules. A failed navigation grant never suppresses separately authorized file calls, and disposing the composition never grants or revokes their authority.
- **ID-S05**: A `PreparedToolRootScope` is valid only inside the awaited callback and is invalidated on return, cancellation or lease closure. The lease serializes this short root operation with disposal and rechecks current authority/stable root object identity after callback completion before returning `Current`; if either changed, the caller discards every derived location/binding and settles any started owned session. Before each JDT protocol request the context obtains the current shared ownership view, rejects an input path inside its verified Ready entry, permits a `VerifiedUnowned` same-name source path, and denies protocol use when the view/binding is unavailable. It maps returned raw locations through the held-root no-follow scope, comparing the first-entry physical identity of any candidate state descendant to the verified Ready record before admitting it. A fresh view immediately before Worker disclosure must retain the same ownership ID/version/entry identity or the call discards all buffered locations/counts/limits; a transition from unowned to owned, owner drift or unavailable view also discards them. Last-write time on the held root may change when owned `.codegraph` is created; neither lease treats that alone as replacement or source-byte proof. Long-running navigation and disclosure stay outside the short callback, with live authority checks. A copied physical launch binding is revalidated immediately before launch and never reaches Agent code.
- **ID-S06**: The `.codegraph` ownership record belongs to the dedicated prepared workspace, not to a disposable lease or Worker, and persists in application metadata outside the entry, inaccessible through model-visible Worker tools but not claimed OS-inaccessible to the pinned native child. One versioned compare-and-set lifecycle is `Absent` draft → durable `Creating` → durably committed `Ready` with non-null observed entry identity → durable `Disposing` → verified `Removed`, or `Quarantined` on uncertainty. A preexisting entry, identity change, reparse substitute, lost record or failed create/commit is never adopted or recursively removed by name; `Creating`/`Disposing` after restart is unavailable pending explicit owner resolution. Later CodeGraph-purpose leases, 18.3's reader and 18.2's JDT context consume the same current verified ownership view. `VerifiedOwned` identifies only the loaded Ready physical entry, `VerifiedUnowned` includes a positively unowned same-name source entry, and `Unavailable` grants neither classification nor JDT protocol/payload access. Stale caller copies are replaced only by a newly verified current record; transition/terminal versions yield no positive binding. At workspace disposition, stop new leases and settle native children/handles, match the trusted current approval to the `Ready` record, and persist `Disposing` before physical removal. Fresh source/tool/owner/readiness and root/recorded-entry checks precede each bounded removal chunk; post-removal checks prove authority/root and entry absence before `Removed` commits and is read back. A revoked lease cannot authorize cleanup. Denied/unavailable authority, process uncertainty, failed post-check or failed terminal commit quarantines and never claims reusable state. No concrete durable store or trusted workspace manager is present in current source; without an exact application-held binding and qualified store, JDT navigation and CodeGraph ownership views stay unavailable.

### Async and Cancellation

- **ID-A01**: Bound issuance, readiness, queue wait, navigation call, authority check and shutdown. Serialize shared protocol operations while concurrent safety is unproven. Cancellation removes a waiter or settles the active operation without delivering late results to another request. Retire an unhealthy/timed-out session before reuse.

### Failure and Retry

- **ID-F01**: At issuance, before source/protocol use, between bounded work chunks and immediately before response disclosure, verify the exact current approval and separate navigation purpose. For JDT request/location eligibility also require a current shared CodeGraph ownership view from the trusted exact workspace binding: missing binding/store, `Unavailable`, a changed ownership version/entry or a failed post-view check denies protocol use or discards all buffered locations/counts/limits, never treating uncertainty as unowned. Revocation, changed approval, expired grant, unavailable verifier or disposal latches navigation authority closed, cancels owned activity and discards payload across concurrent calls. A restored approval requires new issuance. Distinguish these from host `PATH` invisibility, readiness/protocol failure, cancellation, timeout and classpath/capability limits; sanitize outcomes without source, physical path, approval/subject or outside-root metadata. Command invisibility that blocks qualification is a pause/report condition, not a silent alternate launch.
- **ID-F02**: Retry only a new bounded attempt after the failed owned session is fully settled and the same grant remains valid. Never auto-restore dependencies, switch root/adapter or replay uncertain results. Separately granted 18.1 file tools remain usable when navigation is limited; CodeGraph remains required (O-FR04–O-FR06).
- **ID-F03**: A trusted path lease, trusted command candidate, caller assertion or relative-URI filter does not constrain JDT-LS process reads/writes or children. The OS-enforcing launcher must apply a least-privilege child boundary before executable code runs: selected prepared root read-only, writable disposable JDT state separate, and unrelated host files inaccessible except declared JDT/Java runtime inputs; the fixed batch interpreter and every script/Java descendant remain inside it. A Windows Less Privileged AppContainer with an explicit child package/capability identity, narrow resource grants, inherited-handle allowlist and owned child-tree lifetime is a candidate, not qualified or approved host configuration. Its redirected profile/temp bytes count as disposable state; host executable/runtime directories must be independently verified as approved and non-writable by Worker/tool children. Fixed initialization settings disable automatic Maven/Gradle import, build and dependency restoration, but serialized settings alone do not prove their effective behavior. Reject candidate/identity changes before launch, unsafe interpreter/child behavior and any unavailable OS boundary; never fall back to a later PATH candidate or broader process permission. Shared host ACL/PATH/profile changes and native starts require separate authority. If a bounded OS profile cannot be established, navigation remains unavailable pending architecture correction.
- **ID-F04**: The application-owned state operation refuses wrong purpose, wrong/changed batch/Repository/subject/approval/root, non-dedicated workspace, non-owned or already present `.codegraph`, reparse/identity drift, traversal, alternate state names and mutation outside the held subtree. A failed or cancelled operation cannot report success before post-check; if a write may have occurred just as authority was lost, quarantine the workspace and allow only identity-checked disposition cleanup after fresh exact source/tool-purpose/owner verification. These checks do not restrict the pinned native CodeGraph child's inherited host filesystem or network rights. Under the user's narrow direct-child exception, Story 18.3 must observe native effects, block readiness on any write outside the owned `.codegraph` state or change to source/configuration/hooks, and report unverified external access and network effects. This is a post-run readiness condition, not preventive OS isolation or execution permission.
