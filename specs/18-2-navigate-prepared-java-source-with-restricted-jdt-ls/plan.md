# Implementation Plan: Navigate Prepared Java Source with Restricted JDT-LS

**Branch**: `codex/18-2-plan` | **Date**: 2026-09-29 | **Spec**: [spec.md](spec.md)

**Input**: Story 18.2 of `docs/bmad/planning-artifacts/october-release-epics.md`, the September 26 October proposal, this feature's specification, the integrated Story 18.1 contract at `specs/016-contained-source-tools/contracts/prepared-source-tools.md`, and the user's dedicated in-place CodeGraph policy. Earlier plan-review-01–08 and definition-review-01–06 remain in history but do not accept this changed scope; repeat affected gates.

## Summary

Offer bounded definition and reference navigation through an application-bound JDT-LS tool over one whole operator-prepared Java Repository. Preserve Story 18.1's `PreparedSourceContextIssuer` and `IPreparedSourceReadContext` unchanged: they provide only list/read/search and do not expose a physical root. Story 18.2 owns the shared trusted physical-workspace lease. Its separate `CodeGraphPreparation` purpose can establish exactly one application-owned `.codegraph` entry inside an explicitly dedicated Vulgata-managed prepared workspace; no other in-root write is granted. Story 18.3 owns CodeGraph adapter/index/session use and ordinary-reader traversal repair. Keep JDT-LS state separate from source; disable automatic Maven/Gradle import, build and dependency restoration. Validate raw JDT protocol URI strings before `System.Uri` normalization and return only contained Repository-relative observations with truthful limits after a fresh pre-disclosure check. Qualify real navigation, source no-write behavior and subprocess containment in the declared host profile.

This is a material agent-tool and shared authority change under `AGENTS.md`: fresh independent plan review and planned-change authorization precede corrected tasks. The user's in-place CodeGraph choice sets direction but is not approval of this exact plan. Subsequent delivery depends on accepted review, a separately authorized shared-workspace checkpoint for 18.3 consumption, and ordinary downstream gates.

## Technical Context

**Language/Version**: .NET 10/C#; JDT-LS and Java commands assumed available on the host `PATH`, subject to later runtime/profile qualification. Command visibility does not establish Java version, navigation or restricted behavior.

**Primary Dependencies**: Integrated 18.1 `PreparedSourceApproval`, `IPreparedSourceCurrentAuthorityVerifier`, `PreparedSourceContextIssuer`, `IPreparedSourceReadContext` and `PreparedSourceLocation` semantics; existing Infrastructure StreamJsonRpc/JDT-LS mechanisms. The shared trusted workspace seam is Story 18.2-owned and separately released to Story 18.3 after a verified checkpoint. Trusted Infrastructure resolves the JDT-LS and Java commands from the host `PATH`; neither config-file executable selection nor test-local `.env`/`JDT_LS_BIN` is required.

**Storage**: Disposable JDT-LS data/configuration remain separate from prepared source. In the dedicated Vulgata-managed workspace only, a `CodeGraphPreparation` lease may establish and operate one application-owned `.codegraph` entry; its ownership record and physical identity must survive individual lease disposal until workspace disposition. The lease itself is process-local. No database, Knowledge schema, source copy, Source Snapshot, Git revision identity or repository-wide hash is introduced here.

**Testing**: Honest behavioral RED/GREEN in `tests/Vulgata.Tests`, controlled seam tests, then real JDT-LS definition/reference and subprocess qualification under the accepted implementation route.

**Target Platform**: October host-run profile; generic Docker deployment target remains outside this October delivery slice.

**Project Type**: Internal Worker tool and Infrastructure adapter in the existing modular monolith.

**Performance Goals**: Bounded readiness/request/queue/shutdown, one owned session per selected Repository, serialized unsafe protocol work. No completeness or throughput promise.

**Constraints**: Prepared source files and unrelated entries remain unchanged; only the explicitly declared `.codegraph` tool-state subtree is writable under the CodeGraph purpose in a dedicated Vulgata-managed workspace. No arbitrary path, source write, general root write, command tool, dependency restoration or silent result truncation. A physical path lease or checked state path is not subprocess confinement. Required native CodeGraph integration remains Story 18.3-owned.

**Scale/Scope**: One whole Java Repository per grant, with concurrent Workers sharing at most one owned session. No other LSP or multi-session policy.

## Constitution Check

**Pre-research**: Constitution I/V require Core to own contracts, Infrastructure to own filesystem/process adapters and Agents to use injected capabilities, never arbitrary host access. IV requires honest RED/GREEN and actual tool qualification later. AD-15 and PRD FR-15.1–15.3 permit the temporary restricted profile. The October proposal specifically narrows source origin and deployment to operator-prepared host directories. No Constitution exception is proposed.

The shared lease has a separate tool-purpose check, exact current-authority checks, and no model-visible path. A positive `.codegraph` ownership record, no-follow state operations and workspace disposition govern the narrow in-root exception; ordinary source remains read-only. Direct-root JDT-LS no-write and both tools' child-process confinement remain real qualification dependencies. Failure returns to definition/architecture and affected gates.

## Implementation Design

### Responsibilities

- **ID-R01**: Trusted application composition selects the exact `PreparedSourceApproval` tuple (batch, Repository, subject, `WorkerSourceRead` purpose, approval/root-binding identities, operator label), physical root and JDT-LS profile. An additional application-selected tool purpose must authorize navigation; `WorkerSourceRead` alone is not unrestricted tool permission. Infrastructure owns workspace/process authority; Agent functions receive no physical root. This follows integrated 18.1, O-AR02/O-NFR01 and Constitution I/V.
- **ID-R02**: The navigation module translates requests and JDT-LS replies to bounded Repository-relative observations and limitations. It does not create source identity, accept Knowledge, infer a missing relationship from no result, own 18.1 file tools or replace CodeGraph (O-FR04–O-FR06; PRD FR-4.9/15.2).

### Interfaces

- **ID-I01**: One Worker-facing `PreparedJavaNavigationFunctions` construction surface borrows an issued navigation context and creates only definition/reference functions. Calls accept canonical Repository-relative Java path, one-based position and bounded result controls; return `repositoryId` and sanitized navigation outcome. Neither calls nor constructor can issue/change grants, choose a physical root, adapter or executable. The trusted caller owns async disposal after calls settle; cancellation is per call. See `contracts/navigation-tool.md` for callable shape. Preserve 18.1's three-function `PreparedSourceFunctions.Create()` exactly.
- **ID-I02**: Return observed relative path/range locations, request kind, explicit result bound/limit status and capability/classpath/failure classification. Zero locations mean `no result observed`, never absence proof. A capped LSP response is limited without an implied continuation. Withhold outside-grant URIs, physical paths and source content.
- **ID-I03**: Keep JDT-LS stdio, command resolution and the fixed restricted profile behind Infrastructure. Explicitly walk the host `PATH` entries in order for only `jdtls.exe`/`jdtls.bat` and `java.exe`; do not invoke a bare command or Windows ambient executable search. Treat empty/relative/current-directory entries or two supported JDT names in the same first matching entry as invalid resolution, not fallback lookup roots. Reject the first matching candidate if its canonical directory or any reparse-point ancestor lies in or can redirect into prepared source, disposable tool state, an unintended current directory or another host-untrusted entry; do not skip it for a later candidate. Require a regular non-reparse file of the expected extension under a host-approved executable directory protected from Worker/tool writes. Open and pin canonical path, file identity and content digest for the session, hold protection against replacement where supported, recheck identity immediately before absolute-path launch, and fail closed on mismatch. The approved process profile also governs any fixed `cmd.exe` interpreter and its children when the selected JDT command is a batch file; child `PATH` is constrained to approved resolved tools/system inputs. No model-selected command, config-file executable override, user-profile fallback or `.env`/`JDT_LS_BIN` discovery. If either command is invisible in the running host (including a stale process environment after a recent `PATH` edit) and blocks qualification, pause and report; do not guess another path. Resolved visibility is not runtime qualification. Models cannot select adapter, executable, workspace, import/build mode or host path (PRD FR-15.1/15.3; AD-15).
- **ID-I04**: Story 18.2 supplies `PreparedToolWorkspaceIssuer` in Infrastructure with a mandatory current-authority/tool-purpose verifier and `IssueAsync` taking trusted application-held grant/root, selected tool purpose and cancellation; it returns a status plus nullable process-local lease. The lease exposes lifetime/Repository ID to trusted composition and its physical root only to Infrastructure adapters, with bounded `CheckCurrentAsync` and `IAsyncDisposable`. For both JDT and CodeGraph purposes, pin stable root object identity (volume/file index) rather than mutable parent-directory last-write time; in-place `.codegraph` entry creation must not close a still-current JDT lease. This still rejects root replacement, while source-file unchanged claims require separate protected process and per-file evidence. A missing verifier, unauthorized purpose or unmatched tuple fails closed. Story 18.3 consumes this JDT-independent seam after its separately authorized verified checkpoint; exact shape is in `contracts/navigation-tool.md`.
- **ID-I05**: Add one October-specific `PreparedJavaNavigationContextFactory` in Infrastructure, constructed by trusted composition with a fixed `PreparedJavaNavigationProfile` and injected `IPreparedJdtLsRuntime` (controlled test implementation or later qualified production implementation). `OpenAsync(PreparedToolWorkspaceLease, CancellationToken)` accepts only a current `JdtNavigation` lease, returns `PreparedJavaNavigationOpenResult` with exactly one `IPreparedJavaNavigationContext` on `Opened` and null otherwise, and never accepts `AnalysisScope`, a model path, adapter name or executable. The runtime seam lets controlled tests observe process start/disposal and supply protocol replies without a real launch; pre-return failure reports sanitized status and cleanup confirmation through the trusted-only `PreparedJdtLsOpenFailureException` so the factory can release or quarantine its slot honestly. Production composition remains fail-closed until the accepted trusted-PATH/process-profile work. See `contracts/navigation-tool.md` for callable shape/statuses.
- **ID-I06**: Preserve the existing `internal` Infrastructure-only `PreparedToolWorkspaceLease.UseContainedRootAsync(expectedPurpose, callback, cancellationToken)` operation and its `PreparedToolWorkspaceCheckStatus` result. Its short-lived `PreparedToolRootScope` supplies trusted physical binding and separate JDT state-root validation. Replace its `Uri`-only result mapper with a raw protocol-string validation entry point: the protocol adapter passes the JSON-decoded but not URI-normalized location string, the scope rejects device/extended-length/UNC, query/fragment, encoded path-syntax and noncanonical file forms before parsing, then uses handle-relative no-follow containment to yield only `PreparedSourceLocation`. No root path, handle, identity or raw URI becomes a public/model result. The operation checks exact live approval, tool purpose, deadline and pinned root identity before and after the bounded callback. See `contracts/navigation-tool.md`.
- **ID-I07**: Add a separate internal `CodeGraphPreparation`-only owned-state operation on the shared lease, not a general write flag or extension of `IsSeparateDisposableStateRoot`. Trusted application composition supplies a positive dedicated-workspace ownership binding for exactly the canonical `.codegraph` root entry; absent/foreign/preexisting/unverifiable ownership fails closed. The operation uses held-root-relative, no-follow create/open/descendant/remove primitives, requires exact current source and tool-purpose authority around each bounded mutation, and returns only sanitized status plus a short-lived trusted state handle. Creation is exclusive and records physical identity; later leases validate that identity and ownership rather than adopting a matching name. For disposal, the internal coordinator injects the existing `IPreparedSourceCurrentAuthorityVerifier` and `IPreparedToolUseAuthorizer` and accepts the trusted current `PreparedSourceApproval` as a callable input. It matches that approval to the positive record and freshly verifies exact source approval, fixed `CodeGraphPreparation` purpose and the ownership verifier's disposition-ready condition (stopped grants, settled child/handles) before and after bounded identity-checked cleanup; it never borrows a revoked lease. No Worker/Agent argument can name a state entry or receive its path. The positive binding is also the producer input to 18.3's reader repair, while its native returned excerpt verification can reuse 18.1's bounded held-root-relative `ReadTextRangeAsync` under the same exact grant after that repair is qualified. See `contracts/navigation-tool.md`.

### State and Lifetime

- **ID-S01**: Key session ownership by the selected Repository binding from F0; permit at most one live JDT-LS process per selected Repository in the host. Root/profile conflict cannot reuse it. Acquisition and release include protocol, queue, process and disposable data/configuration; waits or busy results are bounded.
- **ID-S02**: Use the prepared Repository as source project root with separate disposable JDT-LS `-data` and configuration. Do not mirror/copy source, invent Git identity or use `PreparedRevisionJdtLsWorkspaceLeaseProvider` as an October grant. Qualification must establish no writes to prepared source; a failure returns for reviewed design correction.
- **ID-S03**: Each trusted lease binds the exact approval tuple, one selected tool purpose and stable observed root object identity. JDT-LS may retain its `JdtNavigation` lease for one bounded session while a separately authorized CodeGraph-purpose lease creates its owned state; the expected parent-directory metadata change is not root replacement. The purposes never share a lease or permission. Either closes on revoked/mismatched/unavailable authority, root object replacement, deadline, cancellation or disposal, cancels owned work and is never cached/reopened under restored approval. This object-identity rule does not weaken 18.1's ordinary reader `ChangedInput` semantics or prove source-file bytes unchanged. Process termination and tool-state cleanup remain adapter-owned; the shared issuer adds no JDT dependency for 18.3.
- **ID-S04**: Ownership changes only at a successful return from injected `IPreparedJdtLsRuntime.OpenAsync`: until then the runtime owns and settles every process, protocol and disposable-state resource it acquires, including on exception/cancellation before return. The factory owns the one-session slot, maps failed/cancelled open to sanitized null-context status and releases that slot only after runtime settlement is confirmed; it cannot dispose runtime partials it never received. A trusted `PreparedJdtLsOpenFailureException` with `CleanupConfirmed=false`, or an unexpected exception with no cleanup attestation, maps to `PreparedJavaNavigationOpenStatus.CleanupUnconfirmed` with null context, quarantines the Repository slot and blocks further runtime open/retry until owned-resource resolution. If surfaced to a Worker, map to existing `ConfigurationUnavailable` with empty payload. If a session is returned but later lease/profile validation, cancellation or context construction fails, the factory disposes that returned session before releasing the slot. After successful context handoff, the context owns/disposes the returned session and releases the slot after Worker calls settle. The context borrows the separately issued workspace lease; the trusted caller always disposes the lease after the context, or after failed open. No failed/disposed context or partial session is reusable.
- **ID-S05**: A `PreparedToolRootScope` is valid only inside the awaited callback and is invalidated on return, cancellation or lease closure. The lease serializes this short root operation with disposal and rechecks current authority/stable root object identity after callback completion before returning `Current`; if either changed, the caller discards every derived location/binding and settles any started owned session. Last-write time on the held root may change when the owned `.codegraph` entry is created; neither JDT nor CodeGraph leases treat that alone as replacement or as proof of source-file change. Long-running navigation and Worker disclosure occur outside the callback, with separate existing during-use and pre-disclosure checks. A copied physical path is confined to a trusted adapter launch binding and is revalidated immediately before launch; it is never returned to Agent code.
- **ID-S06**: The `.codegraph` ownership binding belongs to the dedicated prepared workspace, not to a disposable lease or Worker. It retains exact approval/root/workspace-owner identity outside `.codegraph` and, after exclusive contained creation, the root entry's stable observed object identity; a preexisting entry, identity change, reparse substitute, lost ownership record or uncertain partial create is quarantined, never adopted or recursively removed by name. Subsequent CodeGraph-purpose leases and the 18.3 reader's positive state classification use the same independently verified record, never just the entry name. At workspace disposition, stop new leases and settle the native CodeGraph child and all active handles; the injected owner verifier reports disposition readiness, and trusted composition supplies its currently selected approval to `DisposeOwnedStateAsync`. The coordinator reopens the pinned root no-follow, matches that approval to the record, freshly checks exact source/tool-purpose/owner authority, disposition readiness and root/recorded-entry identity before each bounded removal chunk, and removes only the recorded entry. After removal, it repeats current authority/owner/readiness and root-object checks and verifies absence of the recorded entry; it cannot compare the removed entry's identity. A revoked lease cannot authorize cleanup; if current authority is denied/unavailable, process settlement is uncertain, or the post-check/cleanup is incomplete, quarantine the workspace and report a sanitized failure rather than risking unrelated deletion or claiming reusable state.

### Async and Cancellation

- **ID-A01**: Bound issuance, readiness, queue wait, navigation call, authority check and shutdown. Serialize shared protocol operations while concurrent safety is unproven. Cancellation removes a waiter or settles the active operation without delivering late results to another request. Retire an unhealthy/timed-out session before reuse.

### Failure and Retry

- **ID-F01**: At issuance, before source/protocol use, between bounded work chunks and immediately before response disclosure, verify the exact current approval and separate navigation purpose. Revocation, changed approval, expired grant, unavailable verifier or disposal latches the navigation authority closed, cancels owned activity and discards every buffered location/count/limit detail across concurrent calls. A restored approval requires new issuance. Distinguish these from host `PATH` command invisibility, readiness/protocol failure, cancellation, timeout and classpath/capability limit; sanitize outcomes without source, physical path, approval/subject or outside-root metadata. Command invisibility that blocks qualification is a pause/report condition, not a silent alternate launch.
- **ID-F02**: Retry only a new bounded attempt after the failed owned session is fully settled and the same grant remains valid. Never auto-restore dependencies, switch root/adapter or replay uncertain results. Separately granted 18.1 file tools remain usable when navigation is limited; CodeGraph remains required (O-FR04–O-FR06).
- **ID-F03**: A trusted path lease, trusted command candidate and relative-URI filter do not by themselves constrain JDT-LS process reads/writes or child launches. The host profile must prove a separate least-privilege process boundary: selected prepared root read-only, writable disposable tool state separate, and unrelated host files inaccessible except declared Java/JDT runtime inputs. Disable automatic Maven/Gradle import/build/restore. Reject candidate/identity changes before launch, unsafe interpreter/child behavior and any unsafe launch profile; never fall back to a different PATH candidate or broader process permission. If this cannot be established, navigation is unavailable pending architecture correction.
- **ID-F04**: The owned-state operation refuses wrong purpose, wrong/changed batch/Repository/subject/approval/root, non-dedicated workspace, non-owned or already present `.codegraph`, reparse/identity drift, traversal, alternate state names and mutation outside the held subtree. A failed or cancelled operation cannot report success before post-check; if a write may have occurred just as authority was lost, quarantine the workspace and allow only identity-checked disposition cleanup after fresh exact source/tool-purpose/owner verification. The lease does not make a native CodeGraph child obey these checks: Story 18.3 must qualify child filesystem/network confinement so the child can write only its owned state and declared runtime inputs while source stays unchanged. Until that evidence exists, native in-place preparation is unavailable, not implicitly authorized by this plan.

### Reuse and Locality

- **ID-L01**: Reuse current StreamJsonRpc stdio, bounded request, process cleanup and relative mapping only after direct-root assessment. Current `AnalysisScope`/`ProfiledRevision`, revision lease, project mirror/copy, Windows configuration and empty-as-success parsing are not accepted October semantics. Concentrate binding/containment/normalization in the navigation module, not Worker callers.
- **ID-L02**: Reuse integrated 18.1 `PreparedSourceApproval`, `IPreparedSourceCurrentAuthorityVerifier`, `PreparedSourceLocation` semantics and fail-closed issuance/check cadence, without modifying `PreparedSourceContextIssuer`, `IPreparedSourceReadContext` or list/read/search. Keep CodeGraph native MCP and Scan Control scheduling with their owners. The shared trusted workspace lease and narrow positive `.codegraph` state binding are delivered for separately authorized 18.3 reuse; no reader/filter implementation moves into 18.2 (O-AR06/O-AR07).
- **ID-L03**: The current `JdtLsAnalysisSessionFactory.OpenAsync(AnalysisScope)` and its prepared-revision lease remain historical and must not be wrapped as an October grant. Reuse only its verified stdio/protocol/process mechanics behind the new injected runtime; keep its old callers intact and concentrate October grant validation, result mapping and lifecycle in the new factory/context seam.

## Dependencies and Verification Limits

1. **18.1 integration**: The accepted `PreparedSourceApproval`, current verifier, issuer, read context, location and fail-closed outcome semantics are now integrated. Its Worker context has only list/read/search, no physical workspace. This corrected plan consumes that baseline without changing it.
2. **Shared workspace checkpoint**: Parallel Development assigns Story 18.2 the purpose-bound lease and positive `.codegraph` owner binding/types/tests. Story 18.3 owns the native CodeGraph adapter, index, session and the `PreparedSourceReadContext.cs`/agreed `PreparedSourceTraversal.cs` reader/continuation repair; 18.8/18.12 consume the integrated result later. The lease does not yet support in-root state and must pass fresh plan review, planned-change authorization, corrected tasks, complete-definition review and implementation approval before its shared edit. Story 18.3 waits for an identifiable verified checkpoint and separate integration authority; the ownership decision itself is neither plan nor implementation approval.
3. **Process confinement**: Present JDT `initialize` has no evidenced Maven/Gradle disabling settings and the revision lease copies source. The trusted lease does not prove subprocess containment. Future JDT qualification must establish fixed settings, least-privilege process access, useful navigation and no source writes. Story 18.3 must separately establish native CodeGraph child filesystem/network confinement to its owned `.codegraph` subtree, read-only source and declared runtime inputs; that host-level condition remains unverified and blocks safe in-place native preparation. This plan claims neither qualification.
4. **Qualification sequence**: The user chose a small owned representative fixture first, then the prepared registration/login Repository when supplied. Evidence from the fixture cannot be promoted to the later Repository or universal Java completeness. Real JDT-LS qualification resolves JDT-LS and Java on the host `PATH`; a missing command that blocks the run is paused and reported. The currently observed `jdtls.bat` and `java.exe` visibility is static host evidence only, not navigation or containment proof.
