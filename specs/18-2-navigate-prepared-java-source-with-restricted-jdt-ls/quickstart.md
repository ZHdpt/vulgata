# Story 18.2 Validation Guide

Use `spec.md`, `contracts/navigation-tool.md` and `data-model.md` as expected behavior. Execute the scenarios under the accepted task ownership, resource authorization and verification gates.

## Preconditions

1. Use the integrated, verified Story 18.1 `PreparedSourceApproval` and current-authority verifier; preserve its issuer/context/functions unchanged. Re-accept the corrected 18.2 plan and obtain the applicable planned-change authorization before tasks. Authorize and verify the 18.2-owned shared trusted-workspace checkpoint separately before 18.3 consumption.
2. Establish explicitly owned fixture directories, writable tool state and process resources. Resolve JDT-LS and Java from ordered host `PATH` entries using exact supported names, reject an untrusted first match, pin a validated absolute command identity and recheck before launch. Do not use a config-file executable override, user-profile fallback or `.env`/`JDT_LS_BIN`. If either command is invisible and blocks the run, pause and report the blocker; a recent host `PATH` edit may require a fresh process before it is visible. The currently observed `jdtls.bat`/`java.exe` paths prove only command visibility, not trust, launch or navigation. Assess any batch/interpreter child launch under the same restricted process profile.
3. Confirm automatic Maven/Gradle import, build and dependency restoration are disabled. Establish an actual least-privilege subprocess profile with selected prepared source read-only, separate writable `-data`/configuration and unrelated host files inaccessible except declared Java/JDT runtime inputs. A path lease, startup flag or documentation statement is insufficient.
4. For controlled T010/T011/T013/T018 verification, construct the October `PreparedJavaNavigationContextFactory` with trusted profile and injected fake `IPreparedJdtLsRuntime`; supply an already issued current `JdtNavigation` lease. Check `Opened` gives one context and failures give none. Make the fake acquire a partial resource then throw/cancel before returning: assert the fake runtime itself cleans it, while the factory maps status and frees its slot. A typed unconfirmed-cleanup failure or unexpected exception yields `CleanupUnconfirmed`/null context and an unavailable slot; a second open must not invoke runtime, and any Worker projection is empty `ConfigurationUnavailable`. Make the fake return a session before a later factory validation/cancellation failure: assert the factory disposes that returned session. On successful handoff, assert context disposal settles the session, then the caller disposes its separate lease. Record zero real process starts. Keep production-capable runtime composition fail-closed until accepted trusted-PATH/process-profile work; never substitute legacy `JdtLsAnalysisSessionFactory.OpenAsync(AnalysisScope)`. A fake cannot establish real JDT `rootUri`, `-data`/configuration or restricted settings; check those through observable production-runtime behavior at T022–T024.
5. Before changing the shared lease, exercise the accepted internal `UseContainedRootAsync` callback with current JDT purpose and a separate CodeGraph-purpose lease. Prove state root outside the prepared root, valid contained `file:` URI to relative location, and rejection of wrong purpose, revoked/unavailable approval, expired/disposed lease, root replacement, callback cancellation, overlapping/reparse state root, non-file/outside/encoded-traversal or symlink-escaping URI. Check only sanitized status and relative locations leave the callback, no public root/path/handle appears, and changed authority discards buffered mappings. This is controlled lease/URI evidence; process isolation and real JDT navigation remain separate qualification.

## Fixture-first qualification

1. Prepare a small owned Java Repository with a declaration and caller; note expected definition and reference locations. Issue the trusted workspace lease with exact 18.1 approval plus separate `JdtNavigation` purpose, then exercise the production Worker navigation interface.
2. Record actual definition and reference protocol outcomes and relative locations. Record observed classpath/capability limits and compare source before/after for writes. Initialization alone is not a pass.
3. Exercise missing verifier/tool authorizer, wrong tool purpose, foreign/traversing/symlink input and out-of-root returned URI; verify withheld locations and no outside-root disclosure. Revoke/change approval or make either verifier unavailable at issuance, during use and immediately before disclosure with multiple buffered requests. Verify every response releases zero payload and the closed lease cannot resume without new issuance. Exercise overlap, cancellation, timeout, readiness failure, failed navigation and owned cleanup without touching unrelated processes.
4. Confirm 18.1 file tools remain independently available under their own grant when JDT-LS is limited, and do not mark CodeGraph satisfied by that fallback.
5. In an owned controlled PATH fixture, place a candidate `jdtls.bat` or `java.exe` under prepared source or disposable tool state ahead of a trusted command; also exercise empty/relative/current-directory entries, reparse redirection, unsupported extension/type and candidate replacement after resolution. Every untrusted first match must start no process and must not fall through to a later command. Confirm the resolved interpreter and children use the approved process boundary and constrained child PATH. These controlled cases prove selection checks, not real navigation.

## Prepared Repository follow-up

After the prepared registration/login Repository is actually supplied and access is authorized, repeat representative definition/reference navigation with its real grant and declared profile. Report fixture and prepared-Repository outcomes separately; neither proves universal Java completeness. If direct-root operation writes source, escapes the process profile or useful navigation is impossible under the restricted profile, stop and return a design finding for architecture review rather than copying or changing the input.

## Evidence limits

Controlled fakes verify tool seams and failure handling; a real JDT-LS run through host `PATH` verifies this host/profile. Record exact source/profile and result classifications. The separate Story 18.3 shared-workspace checkpoint must prove its JDT-independent callable contract before authorized consumption; it does not qualify CodeGraph itself. Preserve static, controlled-test and real runtime evidence distinctions under `docs/agents/testing.md`. For Windows native traversal failures, apply `docs/project-lessons.md`: compare launcher permission modes and native status before changing containment code.
