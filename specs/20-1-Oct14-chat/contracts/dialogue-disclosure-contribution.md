## 3. Exact size proposal: execution budget is not a schema limit

Existing execution defaults are deployment-overridable and immutable per admitted turn: 8,000 Unicode scalars per question; 6 provider rounds; 16 tool calls including refusals; concurrency 2; 16,384 argument bytes; page 20 or stricter policy (canonical absolute page ceiling 100); 65,536 complete content-result bytes; 262,144 aggregate tool-result bytes; 65,536 generated output UTF-8 bytes; 12 history turns/49,152 history bytes; 180 seconds; SSE 2,097,152 bytes/round and 8,388,608 bytes/turn. Prompt loader cap is 32,768 UTF-8 bytes. Current query cap is 512 Unicode scalars. History/SSE constants are not proof of completed enforcement or transport qualification.

The following are **proposed durable protocol maxima v1** to agree before D0 implementation. Byte limits apply to the decoded string's strict UTF-8 unless a serialized envelope is named; array counts and envelope limits both apply. Business may counterpropose without silently changing a canonical Knowledge identity. No varchar/SQL layout is mandated.

| Field or collection | Proposed hard limit |
| --- | --- |
| Question | Nonblank; <=8,000 scalars and <=32,000 UTF-8 bytes (including supplementary characters); preserve exact text |
| AnswerText | <=65,536 UTF-8 bytes; empty allowed; no silent substring clipping |
| OwnerSubjectId | Nonblank, <=1,024 bytes |
| CanonicalDatabaseIdentity / TargetId / SelectionDigest | Respectively <=4,096 / 256 / 4,096 bytes; existing owner strings have no declared maxima, so these caps are an explicit compatibility decision, not new canonical validation |
| ProviderProfileId / ProviderProfileRevision | Each nonblank, <=256 bytes; revision must resolve the exact immutable selected configuration, not an API key or endpoint secret |
| RequestDigest / OutcomeDigest / PromptDigest / HistoryProjectionDigest / dependency payload digest | Exactly 64 uppercase ASCII hex characters, SHA-256 of the agreed canonical bytes; 64 bytes each |
| ClientRequestKey / SaveOperationId / owner/attempt/dependency IDs | Guid, 16-byte value; use canonical 32 lowercase hex form only in digest serialization |
| Fence / Sequence / NextTurnSequence | `long` 1..9,223,372,036,854,775,807; checked overflow refuses further admission |
| RepositoryScope | 1..256 distinct Guids; server-sorted; bound maximum at admission, no truncation |
| SectionId | Null or nonblank <=1,024 bytes; no guessed spelling/offset; requires owner compatibility agreement |
| References / ConsumedReads | Each <=256 targets and each complete serialized array <=524,288 bytes; first-report order for references; all read targets need not be reported |
| SuccessfulChunks / ContentBytes per target | Nonnegative `int` / `long`; successful targets require chunks >=1; bounded by admitted tool count and actual accounted raw content respectively; never substitute projection bytes for ContentBytes |
| HistoryTurnIds | <=12 distinct Guid values in admitted sequence order; exact projection <=49,152 UTF-8 bytes of serialized question/answer/reference context, not durable row size |
| Dependency union | <=4,096 distinct canonical contributors, <=128 origin groups, complete immutable host-only union serialization <=2,097,152 bytes |
| Contributor fields | Reuse exact `Contributor`: enum Kind; nullable Guid RepositoryId/SystemId/AdvisoryRecordId; RootBindingIdentity null or <=4,096 bytes; ContentDigest exactly 64 ASCII hex characters under owner semantics (do not rewrite owner casing) |
| Per-origin dependency metadata | Exact selection identity with caps above; nonempty owner-issued Guid; binding/payload digests 64 bytes; nullable DocumentKind; source history/read IDs are Guids; no free-form reason or display text |
| Complete begin / terminal request envelope | <=1,048,576 / 2,097,152 serialized UTF-8 bytes, respectively; large dependency union is separately owner-issued and referenced by ID, not duplicated into each request |
| Terminal diagnostics | Enumerated reason/finish only; no raw exception/provider text; server-rendered localized messages are not saved authority |

Durable envelope measurement proposal: compact System.Text.Json, camelCase property names, string enum names, default escaping, explicit nulls and no indentation. Digest canonicalization is a separate deterministic encoding: version/domain prefix, properties sorted ordinally, canonical Guid forms, UTC timestamps in a fixed round-trip form, integer numeric values only; scope and dependency sets sorted deterministically, ordered history/references preserved; strict UTF-8 and no Unicode normalization. Canonical payload excludes receipt timestamps and transport authentication secrets. Business must publish the precise encoding and shared golden vectors; neither ordinary serializer output nor record equality over ImmutableArray proves canonical equality.

`RequestDigest` binds the immutable logical begin request: original question bytes, owner and fixed selection/context, request key, profile revision/prompt, selected history/projection/dependencies and original limits. Exclude RequestDigest itself and transport/runtime fields ExecutionOwnerGeneration/ExecutionAttemptId; ownership/fence is verified separately. A retry must resolve the existing key before assembling new history or rereading a now-changed provider profile. `OutcomeDigest` binds originating turn/context, terminal text/state/reason/finish, ordered exact references/coverage, full dependency identity, selected history and generation-end time; operation identity and expected fence also match on replay. Identical retries resend the original payload, not a newly timestamped one.

Before admission, reject configuration that could produce a saved value beyond the agreed durable caps; a larger provider budget is not a schema migration. Reject an oversized input/dependency extension before sending that input to the model. Never drop dependencies to fit. If later output/dependency bounds are exhausted, settle with a sanitized incomplete outcome and only safe authorized retained text. Saved history does not get clipped to the smaller inference budget; omit whole turns in the inference projection. Proposed persistence attempt timeout is 10 seconds per call, separate from the original 180-second generation lifetime; timeout yields indeterminate if submission may have happened, never rollback proof or another generation.

## 4. Required operation semantics

1. **Create/open and begin:** validate current owner/Chat purpose/mode/scope/exact publication, admit one conversation slot in a short transaction, allocate sequence/TurnId/fence, store request digest and original limits. Unique `(ConversationId, ClientRequestKey)` gives same key/same request the existing identity/status with `MayDispatch=false`; changed request conflicts. Another key while any active state exists returns Busy. Authentication failures are metadata-free. An uncertain begin response must be reconciled by key; no provider call before durable ownership is confirmed. A host restart cannot dispatch an existing admitted/running row merely because it reads it.
2. **Run and stop:** only the original live owner/fence dispatches. Browser disconnect removes the bounded subscriber; it neither cancels host work nor frees the slot, extends budgets or starts another request. No live reattachment is promised in this October slice; returning UI may obtain authorized saved/status state. Explicit cancellation, access loss or bounds stop generation. The controlled agent's single-use flag is not storage fencing.
3. **Save:** enter Saving with the same owner/fence; validate current owner and all-input dependencies again. Generation must have stopped and owned request cleanup must be settled (or a separately agreed safe transfer proven) before terminal release. A consumer timeout while borrowed I/O is still alive is insufficient. Atomically persist outcome/text, exact references/coverage, dependency-set binding, sequence receipt and terminal status **and release ActiveTurnId in that same transaction**. No TurnSaved event before committed confirmation. Business decides how its transaction plus fresh authorization prevents an unguarded check-to-save gap; no long transaction spans model/tool work.
4. **Replay/conflict:** same operation/digest/fence returns the same receipt without rewriting; changed digest, competing terminal operation or stale owner/fence cannot overwrite. Terminal commit remains authoritative if permission later changes, but subsequent content disclosure can be denied. Operation reconciliation must distinguish receipt truth from permission to view its contents.
5. **Indeterminate:** after lost acknowledgement keep SaveIndeterminate and the active slot occupied. Lookup absent while the original transaction may commit is Indeterminate, not ConfirmedAbsent. ConfirmedAbsent requires owner storage proof that the submission cannot later commit. Safe identical save or lookup may settle; no new model call, refreshed budget or altered payload. Cleanup ambiguity likewise keeps new work blocked. Lookup conflict returns the existing terminal truth to authorized recovery, never a competing generation.
6. **Orphan:** integration supplies verified execution-owner death, not an age threshold. Business atomically checks expected owner/fence, invalidates it and reconciles any commit that may still settle before recording Interrupted/OwnerLost and releasing the slot. A racing committed terminal wins; replay is idempotent. There is no persisted token journal, so unsaved partial text may be unavailable after process death: record a generic interrupted result rather than inventing/reconstructing text. Restart recovery never regenerates.
7. **History:** select the newest contiguous eligible suffix in sequence order, capped by requested and admitted 12-turn/49,152-byte limits. A non-Completed, denied, unverifiable or non-fitting whole turn is a boundary; do not skip across it to stitch older facts into apparent continuity. Reauthorize every included turn's full original dependency set and current conversation owner/mode, then recheck before provider submission. Preserve qualifications in saved text/context; no summaries or qualifier-stripping. Omission returns a generic context-limit indication, never denied titles/counts. Saved interrupted/failed text can be displayed only with current authority and honest labels; it is never factual inference history.

## 5. Read ledger versus complete inference lineage

**Existing exact ledger behavior:** key is the full `DocumentHandle`, including nullable section. Successful, size-accounted, uncancelled exact content calls credit a chunk keyed by the requested opaque continuation (null means the initial cursor); stored chunk data are next-token string, raw Content UTF-8 byte count and SHA-256. Identical cursor replay adds no second chunk/bytes; conflicting replay is refused. Snapshot projects every consumed target. Reports must refer to those targets, reject invented/foreign targets, accumulate first-report order and deduplicate. Empty report is valid. Search, related navigation and prior-turn references earn no content credit. Report input count is at most the admitted ToolCalls limit.

`IsPartial` currently means the ledger cannot walk an unbroken initial-to-null-next chain; `SuccessfulChunks` counts distinct consumed cursor entries and `ContentBytes` sums raw content bytes. This does **not** prove full corpus coverage, semantic support, complete inference dependencies or absence of `CoverageProjection.PermittedGaps`. Do not promote a false IsPartial value to "complete evidence". The proposed durable contribution carries owner coverage separately. Cursor strings/content hashes are runtime bookkeeping, not durable authority; persist exact targets, aggregate coverage and dependency identity rather than a token transcript. Business must settle proof of chunk-chain completeness/qualifier continuity, especially terminal suffixes and partial sections, before dependent implementation.

**Recommended Business representation:** one immutable, host-only, owner-issued dependency-set identity (`Guid DependencySetId`) resolving to canonical Contributor metadata and origin groups. Reuse Contributor semantics rather than add a Chat access enum. Business retains the set for at least the lifetime of dependent saved dialogue; selection/cursor expiry cannot erase its reauthorization meaning. The identity is never an access grant, never accepted from model/browser, and never serialized into the model-facing tool result or UI. Business chooses whether it stores groups normalized or as its own bounded canonical document; Chat sees an issued envelope and owner validation, not tables.

Proposed `InputKind = Question, Context, Search, Content, Related, History`. Publication may be null only for a verified Knowledge-free question/context; it cannot be absent for a wiki result or reused history. Group scope/mode/purpose must match the actual input authority, and every group uses the set's owner. History references must point to earlier completed turns and immutable parent sets; reject cycles, retain a complete flattened union and do not resolve through today's mutable graph. Existing scalar limits apply to every nested handle/binding/contributor; invalid nullable contributor combinations remain the canonical owner's decision. `KnowledgeInputsAbsent=true` is an explicit owner-validated attestation, never inferred by Chat from an empty array.

Each origin group must bind exact `PublicationBinding`, original mode/Chat purpose, subject identity and canonical scope, payload digest, owner-issued identity, complete contributor union and applicable DocumentKind. Retain exact read handle/relationship or uncertainty selection identity and originating history TurnId where applicable. Recheck groups under their original selection plus current identity/access; a current publication cannot retarget old evidence. Never null out DocumentKind to make CL acceptable in Business. Mixed related/coverage results require owner-grouped mode semantics, not a blanket null-kind bypass. An opaque alternative is acceptable only if it resolves these same immutable semantics after restart and expiry; its wire spelling/lifetime is an owner decision.

The per-turn union monotonically includes dependencies for **everything actually submitted to inference**, across all rounds:

- admitted question/context and any server-supplied advisory facts; question ownership is checked even if it has no Knowledge contributors;
- the exact reused completed history projection and recursively its original inference dependencies, including inputs omitted from those turns' footers;
- successful search/browse titles, excerpts, qualification/provenance and permitted coverage/gaps, even when no discovered Document is read or reported;
- each successful content page, all qualifications/evidence actually supplied, including advisory and hidden transitive contributors required to release it;
- related targets, relationship meaning, supporting/opposing evidence, permitted Uncertainties and coverage metadata, even if neither endpoint is read/cited.

An owner-authorized page and its host-only dependency envelope must describe the same bounded immutable payload, delivered as one logical result (or owner-issued payload-bound receipt). Register and authorize its dependencies **before model input**; no later "fetch dependencies" race that can pair them with another page/publication. Recheck the accumulated union before each released text batch, accepted report/footer, terminal save, history display and history reuse. On denial/outage suppress the affected generated material and cancel work; removing only the footer cannot make prose safe. Previously delivered bytes cannot be recalled. A conservative superset of actually submitted inputs is safe if complete and reauthorized; a subset is not.

No default/empty list stands for missing lineage. A genuinely Knowledge-free question/result requires an explicit owner-validated "no Knowledge inputs" attestation and conversation-owner checks; any search/content/related/history/context dependency invalidates that case. A valid empty footer never licenses an empty dependency set. Unknown lineage is unavailable and prevents dispatch/disclosure. Dependency capacity exhaustion also fails closed before the new input is sent, never silently evicts earlier contributors.

Current contracts cannot represent the returned host-only dependency envelope, whole-result completeness proof, retained union identity, payload-to-envelope binding or historical reauthorization handle. Public EvidenceReference arrays/selected repositories/reader-context token/footers are insufficient substitutes. Canonical policy can evaluate supplied Contributors but cannot establish that Chat supplied all of them. Business must settle the extension and its source of completeness, including source/advisory/transitive/relationship/uncertainty and coverage contributors. Chat must not infer these from internal reader classes.

## 6. Business output-to-Chat byte compatibility

Integrated Business currently checks a **bare ContentPage** with default `JsonSerializer.Serialize` against 65,536 bytes, shrinking at safe text boundaries. Chat measures the **whole OctoberChatToolResult** with camelCase, string enum names, explicit null fields, UnsafeRelaxedJsonEscaping and MaxDepth 16; the SDK receives its JsonElement without another JSON-string quoting layer. Title, handle, repeated claims, qualification/evidence/limitations, coverage, cursor, envelope and escaping all count. Raw Content bytes alone are not the measurement. Default Business escaping may be larger for some text, but a bare-page success still does not establish that the differently shaped Chat wrapper fits. Explorer's 64-KiB evidence proves its own projection only.

Owner agreement must ensure `UTF8(ChatSerialize(new OctoberChatToolResult(Succeeded, Content: page, References: []))) <= min(admitted.ContentBytes, 65,536)` and cumulative actual Chat result bytes <= admitted.ToolResultBytes. Search/related/report results consume that aggregate; the current facade applies the individual content cap only when Content is present. No arbitrary "64 KiB minus N" reserve is accepted without a proven bound for the exact wrapper/serializer. Business may propose a shared bounded projection budget or a demonstrably compatible owner chunk policy; Chat must not truncate a page, invent a continuation, strip qualifiers or grant read credit before the complete result passes accounting. New host-only lineage metadata stays outside model JSON, with its separate durable size limits.
