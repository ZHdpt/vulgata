# Contract: DeepSeek Strict Result Submission

This contract refines the Story 12.3 Worker Agent boundary for the configured DeepSeek-compatible provider. It does not change `code-logic/file-v2`, durable retry, dispatch, persistence, the provider circuit, or Stories 12.4/12.5. The authoritative result remains the full local schema and semantic validator; provider strict mode is an earlier transport-shape check, not acceptance authority.

## Closed function surface and ownership

The local Worker/FICC composition owns exactly two functions, and both projected declarations carry provider `strict: true`. Every navigation-capable provider request before turn nine advertises both declarations in their fixed order; every finalization-only request advertises only the unchanged projected `submit_code_logic` declaration. Finalization alone is legal on request nine, on request ten only as the correction after an invalid first submission on request nine, and on one earlier correction request after an earlier locally rejected first submission:

1. `navigate_code` is the sole evidence-access function and retains its durable eight-call/eight-attempt, 20-results-per-call, 65,536-total-evidence-byte, depth-three contract.
2. `submit_code_logic` is the sole non-evidence finalization function. Its only model-authored argument is one `code-logic/file-v2` candidate. It never reads source, Documents, CodeGraph, JDT LS, manifests, or another job.

`PreparedPass1JobExecutor` owns the configured endpoint/client, one complete streaming conversation, function loop, deadlines, and submission session. `PreparedPass1WorkerDispatcher` calls it exactly once per durable claim and only maps the returned result; it owns no conversation/retry/budget dictionary. PostgreSQL-backed navigation reservation is the sole cross-retry attempt authority. Candidate parsing/validation and privacy ownership remain unchanged.

The prompt states that free-form assistant text is never a result, the Agent should emit exactly one function call per assistant response, it must use `navigate_code` for evidence, `submit_code_logic` must be the sole finalization call, and one invalid submission may be followed by one corrected submission. This is behavior shaping; the whole-response preflight below remains the safety boundary. No tool result discloses source beyond `navigate_code` or validator detail. A projected correction may disclose only the closed category and deterministic repair code below.

## Execution-local submission state machine

The session starts with `SubmissionCount = 0`, no captured result, and navigation enabled. The prompt requests exactly one call and keeps submission sole. Every final Worker request uses disabled thinking plus mandatory tool selection, so a provider turn must contain one or more calls. Every navigation-capable provider turn before turn nine uses generic `tool_choice:"required"` with both exact strict declarations. Provider turn nine is forced finalization when no earlier submission ended the execution; turn ten is reserved only for the correction after an invalid turn-nine first submission. Every finalization-only request uses exact named `submit_code_logic` choice with the exact one-element unchanged projected strict submit declaration and the Terminal Context Projection defined below. An inner Story-only chat client still preflights the complete assistant response before `FunctionInvokingChatClient` can execute a callback. An all-declared-`navigate_code` response of one through eight calls may pass only while navigation is legal and before turn nine, even when it exceeds exact hydrated durable remaining capacity; only its provider-order capacity-fitting prefix may reserve and invoke, while every excess sibling receives a constant no-effect result. Invocation remains serial and concurrent invocation remains disabled.

| Event | Result |
|---|---|
| One or more authorized `navigate_code` calls before any submission and within all durable/local bounds | Preflight the complete call set with zero durable effect, then before each serial callback commit one next-attempt reservation; continue with one result per call ID. |
| First `submit_code_logic`, locally valid | Atomically capture only the canonical UTF-8 result, mark Accepted, and terminate without another provider request. |
| First `submit_code_logic`, locally invalid on or before turn nine | Increment to one, disable navigation, return only the existing closed tool result, and allow one projected finalization-only request carrying one closed category plus its deterministic repair code. |
| Any `navigate_code` after submission has begun | Terminate as rejected; no evidence access occurs. |
| Second invalid `submit_code_logic` | Terminate as rejected. |
| Any finalization-only request | Project the exact terminal message grammar, advertise only the exact one-element unchanged projected strict `submit_code_logic` declaration, and select exact named `submit_code_logic`; preflight requires a sole legal first or second submission. |
| Provider turn nine carries a sole first `submit_code_logic` | Invoke local validation/capture once; terminate if valid, otherwise continue exactly once to the projected turn-ten correction. |
| Provider turn ten carries the sole second `submit_code_logic` after an invalid turn-nine first submission | Invoke local validation/capture once, then always terminate: accept if valid, otherwise reject; never issue request eleven. |
| Provider turn nine or ten carries navigation, a third submission, a turn-ten first submission, unknown/mixed/multiple-submission calls, or an above-eight response | Terminate as rejected without evidence access or candidate validation. |
| An otherwise legal one-through-eight all-navigation response exceeds current remaining capacity | Reserve/invoke only the provider-order fitting prefix; return `navigation-budget-exhausted` for every excess original call ID with zero excess application effect; continue to a finalization turn. |
| Free-form content on a zero-call completed turn | Ignore as a candidate and reject with zero callback/reservation/receipt/candidate/later-request effect. Required tool choice makes this a provider-contract violation rather than a legal completion. |
| Provider turn ten completes without a valid captured result | Reject; no eleventh provider request. |

The four rejection categories are `InvalidShape`, `InvalidBinding`, `InvalidEvidence`, and `InvalidSemantics`. Their mapping from the local parser's internal errors is total and deterministic. The terminal correction pairs them exactly as follows:

| Category | Repair code | Provider instruction |
|---|---|---|
| `InvalidShape` | `UseMinimalValidDocument` | Rebuild the smallest truthful closed document described by the terminal prompt. |
| `InvalidBinding` | `CopyPacketBinding` | Copy the packet binding property-for-property and value-for-value. |
| `InvalidEvidence` | `UseAuthorizedFullRangeAnchor` | Replace anchors and references with one exact full-range `a001` anchor from the packet. |
| `InvalidSemantics` | `UseMinimalValidDocument` | Discard optional detail and submit the smallest truthful locally valid document. |

The ordinary FICC tool result remains the existing fixed `invalid-*` string. The terminal projection alone receives `{"attempt":1,"category":"<closed-value>","repairCode":"<closed-value>"}`. The repair code is selected solely from the category; it is not parsed from an exception or model output. Candidate bytes, paths, schema fragments, source beyond the unchanged packet, validator messages, and validator internals are excluded. An accepted candidate is not logged, persisted as conversation state, or returned to the provider; termination hands its canonical bytes directly to the current executor result.

Every excess index returns exact constant `navigation-budget-exhausted`, sets no termination flag, and performs no reservation/callback/receipt/evidence/candidate work, allowing FICC to preserve one result per original call ID and continue.

Configure serial invocation, unknown-call termination, no detailed errors, and zero SDK/provider retries. The SDK's maximum is set to eleven only because the pinned SDK removes function declarations on its configured last iteration; this keeps a provider-visible declaration array present on service turn ten, where Vulgata substitutes the submit-only array. A Vulgata-owned custom invoker is the authority for the ten-turn ceiling:

`MaximumIterationsPerRequest = 11` is therefore an SDK compatibility setting, not the Story ceiling. A fake transport must cover navigation-capable string-required requests with the exact ordered two-function array on turns one through eight, an early projected correction request, forced first finalization on turn nine, and the optional correction on turn ten, all with exact named-submit plus the exact one-element unchanged submit array. Total callbacks across durable attempts cannot exceed eight.

## Strict metadata and wire-size bounds

The pinned SDK adapter must expose `strict: true` from `AIFunctionFactoryOptions.AdditionalProperties` through each public `AsOpenAIChatTool()` input. Each streamed provider response is limited to exactly 16,777,216 raw SSE transport bytes under Vulgata's conservative calculation of 32,768 output tokens x 512 serialized SSE bytes per generated token. DeepSeek's official Chat Completions API defines `max_tokens` as the maximum generated tokens and streaming as data-only SSE terminated by `[DONE]`; the provider model page documents a maximum above the retained 32,768 setting.

The raw transport allowance is independent from an exact 16,777,216-byte assembled UTF-8 bound across reasoning, content, tool-call names/IDs/arguments, and their structural framing. ## Final DeepSeek wire compatibility

## Streaming and assistant-call/result continuity

Every provider request is streamed. The five-minute inactivity deadline is measured from the last successful nonzero raw response read, including an SSE `: keep-alive` comment. Raw activity increments an execution-local generation/timestamp but comments never enter assembled content. One outstanding parsed `MoveNextAsync` races against a deadline computed from the latest generation; timeout rechecks generation/time before cancellation, so renewed activity restarts the window without a concurrent move. A zero-byte read, request write, response header, parsed-buffer replay, or local tool execution is not activity. The 25-minute absolute deadline begins once per Worker attempt, never resets, and remains below the 30-minute durable lease. The 2.5-hour qualification command watchdog is outside Worker authority. Zero SDK retries preserves one durable Worker failure retry as the only retry layer.

For every later navigation-capable request, the adapter replays the preceding assistant message's ordinary content and assembled tool calls unchanged and in original order, followed by the corresponding tool results. Tool-call assistant content must be a string: existing string content is unchanged and absent/null content is represented exactly as `""`; any other shape rejects. It may accumulate fragmented transport data, but it may not normalize, summarize, concatenate ambiguously, or omit calls/results. Finalization-only requests are the sole exception and must use the exact Terminal Context Projection, not a partial edit of the historical list. The pinned `Microsoft.Extensions.AI.OpenAI` adapter is proven to parse OpenAI `BinaryData` into `IDictionary<string,object?>` and does not retain encoded outer arguments. The invoker therefore requires exactly one parsed key named `document`, requires its value to be a non-null object `JsonElement`, and passes that element's nested `GetRawText()` directly to the full local parser. Dictionary reserialization and typed model binding are forbidden. Focused adapter tests must prove nested duplicate and unknown members survive `JsonElement.GetRawText()` and are rejected locally; wrong/missing/extra outer keys, wrong value kind, or parse failure reject before the parser. If this seam, ordinary complete content/call/result round-trip, or finalization-only exact projection is not preserved by the pinned adapter, the pre-source fake-wire/handshake gate fails closed. A manual/direct-SDK loop was considered but rejected as a larger ownership surface when the existing FICC plus one delegating projection client retain the authoritative candidate bytes and single session needed by the local parser.

Timeout, malformed stream, missing/invalid parsed arguments, strict-schema rejection, endpoint/model mismatch, authentication failure, network failure, and provider unavailability map through a closed taxonomy: 401/402/403 is nonretryable provider configuration; 400/422 is nonretryable request/capability rejection without credential wording; 408/429/5xx is transient provider unavailability.
