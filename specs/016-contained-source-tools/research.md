# Story 18.1 Research and Decisions

All planning unknowns in `spec.md` are resolved below. These are design decisions derived from repository authority and inspected source, not implementation or runtime evidence.

## Authority and compatibility

- **Decision**: Treat October prepared input as a separate live-source origin with an operator label, never a Profiled Revision or Source Snapshot. **Rationale**: O-FR01 explicitly removes Git operations, fabricated commits, managed snapshots and repository-wide hash prerequisites (`docs/bmad/planning-artifacts/october-release-epics.md:157`); Story 18.1 repeats the boundary (`:596-625`). The glossary distinguishes Repository Scan Run/Profiled Revision/Source Snapshot (`docs/UBIQUITOUS_LANGUAGE.md:25-32,97-100`). AD-3 still governs normal retained Git reads (`docs/bmad/planning-artifacts/architecture/ARCHITECTURE-SPINE.md:58-64`). **Alternative**: Reuse Git identity; rejected because it would falsely imply byte-stable provenance and violate October disposition.
- **Decision**: Apply PRD FR-4.9 scoped-source/tool safety and NFR-2.3 authority to the prepared exception without inheriting FR-4.9's ordinary Git acquisition mechanics (`docs/bmad/planning-artifacts/prds/prd-vulgata-2026-06-12/prd.md:84,198`). **Rationale**: Architecture gateway assigns product disposition to PRD, design to spine, and as-built to code (`docs/bmad/planning-artifacts/architecture.md:14-33`). **Alternative**: Treat older snapshots or code as implicit override; rejected by the gateway and `AGENTS.md`.
- **Decision**: Keep the existing retained-source application/read context unchanged. **Rationale**: Its interface returns ProfiledRevision and ManifestSha256 and offers entry/list/byte/text reads but no search (`src/dotnet/Vulgata.Core/DomainServices/RetainedSourceContracts.cs:3-46,110-190`); its Infrastructure implementation relies on verified retained objects and a manifest (`src/dotnet/Vulgata.Infrastructure/Source/RetainedSourceReadContext.cs:9-47,166-189`). **Alternative**: Generalize it across origins; rejected because it would obscure origin-specific guarantees and threaten FR-011 regression.

## Root authority and containment

- **Decision**: A trusted application-owned issuer binds batch, Repository, approved subject, Worker-source-read purpose, approval identity/epoch, label and configured physical root, then gives the Worker only a context. The model-visible three operations never accept identity/root fields. Inject a current-authority verifier at the Core seam: it checks the exact approval tuple at issuance, operation start, between entries/chunks and immediately before any response release; revoked/changed/unavailable approval closes the context and discards buffered output. The verifier is testable with an in-memory adapter, so direct fixtures need no DB. **Rationale**: O-NFR01 binds roots outside model arguments (`docs/bmad/planning-artifacts/october-release-epics.md:204`); Constitution V and PRD NFR-2.3 require live authority at disclosure (`.specify/memory/constitution.md:136-145`; `docs/bmad/planning-artifacts/prds/prd-vulgata-2026-06-12/prd.md:198`). AD-2/AD-6 place injected tool contracts in Agent Execution and physical tools in Infrastructure (`docs/bmad/planning-artifacts/architecture/ARCHITECTURE-SPINE.md:53-56,82-86`). Retained-source `CheckAvailabilityAsync` rechecks subject, purpose, Repository and binding before/after work (`src/dotnet/Vulgata.Infrastructure/Source/RetainedSourceReadContext.cs:471-566`), illustrating the seam without requiring its DB-backed mechanism. Existing `PreparedNavigateCodeFunction` illustrates server-owned binding outside model arguments (`src/dotnet/Vulgata.Agents/WorkerExecution/PreparedNavigateCodeFunction.cs:10-32,66-115,194-210`). **Alternative**: Trust approval only when issued or expose root selector; rejected because revocation could leave a still-live disclosure capability or broaden host access.
- **Decision**: Make the trusted issuer a public concrete Infrastructure module, `PreparedSourceContextIssuer(IPreparedSourceCurrentAuthorityVerifier)`, with `IssueAsync(PreparedSourceGrantRequest, CancellationToken)` returning a sanitized `PreparedSourceIssueResult`. This is the smallest callable seam for composition and T003 public-seam RED tests; it reuses the Core request/verifier/context types already declared in `src/dotnet/Vulgata.Core/DomainServices/PreparedSourceContracts.cs` and adds no second Core issuer abstraction. Success returns one context; every failure returns status with null context. **Rationale**: T003/T004 name this production issuer but the earlier plan left its callable signature/failure shape open. A single deep module keeps current-authority, root opening and cleanup local while allowing a controllable in-memory verifier in tests. **Alternative**: add an extra Core issuer interface or require tests to reflect private constructors; rejected as a hypothetical seam or a non-public test surface. See [contracts/prepared-source-tools.md](contracts/prepared-source-tools.md#trusted-issuance-and-context).
- **Decision**: Make the Agent adapter one public `PreparedSourceFunctions(IPreparedSourceReadContext)` module with `Create(): IReadOnlyList<Microsoft.Extensions.AI.AIFunction>` returning exactly three ordered, closed-schema functions. It borrows the issued context; trusted composition owns disposal, while invocation forwards cancellation and returns Core results unchanged. Invalid schema is sanitized denied before Core dispatch. **Rationale**: T016/T017 require a public seam; existing `PreparedNavigateCodeFunction.Create` and other Worker functions vary in their creation interface (`src/dotnet/Vulgata.Agents/WorkerExecution/PreparedNavigateCodeFunction.cs:66-115,194-210`), so an exact contract prevents test/implementation owners from choosing different public shapes. One adapter contains translation and schema checking, while authority and filesystem policy remain in the Core/Infrastructure seam. **Alternative**: one factory per tool or a `CreateSession` lifecycle owner; rejected as wider surface and competing context ownership. See [contracts/prepared-source-tools.md](contracts/prepared-source-tools.md#closed-model-visible-operations).
- **Decision**: Reject traversal through all symlinks and Windows reparse points, including links targeting inside the root and reparse components of the configured root. Establish the held root from a trusted volume/directory handle; open each child relative to held parent handles with no-follow semantics and reject link/reparse handles before reading/enumerating. A link can be reported as a limited listing entry if identifying it requires no following. **Rationale**: Lexical-prefix and attribute-then-open checks have a retarget/replacement race; existing `RevisionBoundSourceReader` uses prefix and `HasReparsePoint` for a different revision-bound lease (`src/dotnet/Vulgata.Infrastructure/Analysis/Source/RevisionBoundSourceReader.cs:65-112,186-209`) and is not enough to prove live hostile-tree containment. O-NFR01 requires denial of path/symlink escapes. **Alternative**: Safely follow in-root links; adds platform-specific canonicalization and race complexity without a current requirement. This preference was sent to root as optional input; absent a real reply, the conservative design remains a plan assumption.
- **Decision**: Qualify handle-relative no-follow semantics on the October Windows host. Linux is a broader application target but October does not require Docker/Linux qualification; a Linux adapter may be enabled only after equivalent platform tests, and otherwise fails closed. **Rationale**: October O-NFR12 explicitly targets host execution while `docs/agents/testing.md` requires owned resources. **Alternative**: fall back to `Path.GetFullPath` plus `File.Open`; rejected for TOCTOU exposure. Exact native-call implementation remains a local choice only if it preserves the interface and race invariant.

## Limits, locations, and text

- **Decision**: Use finite default and maximum caps stated in `plan.md` Technical Context, with cumulative atomic budget accounting. **Rationale**: O-FR04 asks explicit limits/continuations (`docs/bmad/planning-artifacts/october-release-epics.md:160`); retained-source caps, budget dimensions and deadline are reusable design examples (`src/dotnet/Vulgata.Core/DomainServices/RetainedSourceContracts.cs:67-120`; `src/dotnet/Vulgata.Infrastructure/Source/RetainedSourceReadContext.cs:45-69,130-155`). **Alternative**: unbounded recursive scan or whole-file read; rejected for O-NFR01.
- **Decision**: Use canonical Repository-relative `/` paths, zero-based UTF-8 byte offsets for read ranges, and 1-based Unicode-scalar line/column plus byte offset/length for literal search matches. Search is case-sensitive ordinal, not regex, and does not filter by extension. Strict UTF-8 with optional initial BOM is the only text decoder for this story. A range splitting a code point is invalid-range; non-UTF-8/binary content is unsupported-text. **Rationale**: precise locations and unfamiliar-extension access are required by FR-002/003 and O-FR04; an explicit decoder avoids platform-default ambiguity. **Alternative**: extension allowlist or replacement-character decoding; rejected because it can hide source or produce misleading matches.
- **Decision**: List/search use ordinal path ordering and bound, one-use, context-local continuation state. Continuation records the exact approval binding, request scope and observed source identity/metadata rather than indexing/hash/copying a whole tree. Any revoked, changed or unavailable approval invalidates all cursors; a restored approval requires a new grant. **Rationale**: FR-001/004/007 require current authorized continued access without retargeting; O-FR01 excludes repository-wide hashing and snapshot retention. **Alternative**: public offset cursors, persisted snapshots or reuse after approval restoration; rejected for forgery, authority drift and out-of-scope retention.

## Truthful completion, lifetime and retry

- **Decision**: Distinguish complete, complete-empty, limited, incomplete, denied, authority-unavailable, missing, unreadable, unsupported-text, invalid-range, changed-input, cancelled and deadline-exceeded. Revocation/changed approval is sanitized denied; verifier failure/unavailability is sanitized authority-unavailable; both discard buffered data and close the context. An incomplete source result may include already permitted partial data and a relative limitation; complete-empty only follows finished traversal with a final current-authority check. **Rationale**: `spec.md` FR-001/004/006/008/009, Constitution V, PRD NFR-2.3 and O-FR04 reject unauthorized or false-absence results. **Alternative**: cached allow or empty arrays on verifier exception; rejected for unauthorized disclosure and misleading absence.
- **Decision**: Treat the operator's unchanged-input statement as an assumption, not a version guarantee. Revalidate held entry identity/metadata around operations and across continuation, invalidate on observed change, and avoid post-cancellation disclosure. Undetectable concurrent changes cannot be advertised as a historical snapshot. **Rationale**: `spec.md` Assumptions/edge cases; no allowed copy/hash/retention. **Alternative**: claim exact atomic tree coverage; impossible from live mutable source without stronger input control and outside scope.
- **Decision**: Link caller cancellation, grant lifetime, authority-loss latch and deadline; close owned handles/streams/iterators on every exit. A revocation signal may cancel active work, while the awaited verifier checks still govern each disclosure; verifier exceptions fail closed. No automatic retry. **Rationale**: FR-001/008, Constitution V and `docs/agents/testing.md` require live authority, truthful interruption and owned-resource settlement. **Alternative**: automatic retry of reads/search after source/authority change; rejected because it can mix versions or hide limits.

## Reuse and test evidence

- **Decision**: Test through the production read/current-authority interfaces with owned prepared trees and controllable in-memory approval, plus Agent function shape/invocation; retain existing Git-bound tests as regression. Revoke or fail the verifier before a call, between chunks/pages and before final release; assert no metadata/content/continuation escapes and all owned activity settles. **Rationale**: existing retained-source tests cover path variants, cursor budgets and read lifecycles (`tests/Vulgata.Tests/RetainedSource/RetainedSourceReadContextTests.cs`; `RetainedSourceReadLifecycleTests.cs`; `RetainedSourceRangeReadTests.cs`), while `RetainedSourceRootMappingTests.cs:16-111` shows Windows root alias risk but uses PostgreSQL and is not a prepared-tree fixture. Story 18.1 requires DB-free direct qualification (`docs/bmad/planning-artifacts/october-release-epics.md:622-625`). **Alternative**: infer live approval safety from old retained tests or a DB fixture; rejected as a different origin/seam and unnecessary test dependency.
