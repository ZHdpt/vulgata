# October Host Provider Binding Contract

For each generator or October Web process, the operator explicitly declares one configuration source and precedence. The provisional route is host-supplied configuration; there is no automatic `.env` path discovery. A later database configuration route requires explicit selection, implementation and, for copied protected rows, verified compatible Data Protection keys, application-isolation identity and protector purpose. Normal provider administration remains unchanged.

Each Worker and Chat role selects a named profile with a complete API type, endpoint, model and protected credential reference from the selected source. The roles may deliberately name the same profile; omission cannot silently collapse them. Validate one profile as a unit: no missing field is backfilled from another source or role, and no provider switch follows validation or runtime failure. Neither the model nor a tool call may choose a credential or endpoint.

The effective host binding is fixed for its process lifetime. Changing source, profile or selected batch requires restart. Binding validation reports configuration identity/presence and sanitized failure class, without exposing key material or making a paid availability call. Provider readiness and generation quality require later separate evidence; a valid binding proves neither.
