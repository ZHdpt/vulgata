# Research: Story 18.3 Native CodeGraph MCP

This is source-grounded research for the user's in-place workspace and later direct pinned-process decision. Completed client/wrapper work and the direct Git/no-Git CodeGraph 1.5.0 fixtures prove controlled native transport and observed local effects, not Vulgata app-bound authority, OS filesystem/network confinement or generic source immutability. Story 18.2 still owns exact entry/write, contained-read and positive-binding capability; Story 18.3 owns bounded reader/native-result corrections. [Direct decision](evidence/user-direct-process-decision-01.json); [direct result](evidence/codegraph-direct-fixture-01.json); [current spec](spec.md).

## Decision 1: Consume the F0 prepared-source authority

**Decision**: Consume integrated Story 18.1's exact `PreparedSourceApproval` tuple, mandatory current-authority verifier and three-function read seam without changing its public contracts. Story 18.2 owns shared source/root authority, lease lifetime and positive app-owned state binding. Story 18.3 owns CodeGraph index/startup/session policy and only the bounded correction to existing Infrastructure list/read/search traversal/continuations needed for its owned state. **Rationale**: The [Core contracts](../../src/dotnet/Vulgata.Core/DomainServices/PreparedSourceContracts.cs), [issuer](../../src/dotnet/Vulgata.Infrastructure/Source/PreparedSourceContextIssuer.cs), [Agent functions](../../src/dotnet/Vulgata.Agents/WorkerExecution/PreparedSourceFunctions.cs) and [accepted 18.1 contract](../016-contained-source-tools/contracts/prepared-source-tools.md) establish live fail-closed approval; physical root/handles remain private. [Updated spec FR-012/SC-009](spec.md) assigns the consumer repair here. **Alternatives**: new root registry, fourth 18.1 function, separate filter descriptor, blanket `.codegraph` name suppression or treating a read lease as a write grant would broaden/misstate authority; reject. **Open dependencies**: verified 18.2 entry/descendant write, contained read and positive ownership binding, plus exact shared file/type agreement. [Owner correction](evidence/source-reader-owner-invalidation-01.json).

## Decision 2: Native tool path

**Decision**: Preserve completed native stdio client and closed Worker wrapper (`ModelContextProtocol.Core` 1.4.1). Retain October's fixed CLI `codegraph init <bound dedicated root>` then `serve --mcp -p <bound dedicated root> --no-watch`, launched directly as the declared pinned 1.5.0 installation with closed stdin and no model/project/process choice. **Rationale**: October selects CLI before native MCP, and the [direct Git/no-Git result](evidence/codegraph-direct-fixture-01.json) observed initialize/list/call and useful `Calc.cs`/`Caller.cs` source with unchanged local fixture source/config/hooks. CLI still offered hook sync on both inputs; closed stdin declined it. [Completed evidence](evidence/implementation-group-03.json) covers controlled client/wrapper behavior. Neither fixture qualifies app binding, external writes/network or the fixture client's path-reopen verification; production uses Story 18.2's handle-relative contained read. **Alternative**: CLI query wrapper, CodeGraphContext, raw `AITool` or simulated discovery fail native/authority obligations; AppContainer/profile was explicitly rejected by the user for this route. **Open verification**: 18.2 capabilities, reader/native containment regressions and selected-host app integration. [Direct choice](evidence/user-direct-process-decision-01.json).

## Decision 3: Scope, lifetime and failure

**Decision**: Qualify discovered `codegraph_explore`, expose only a closed UTF-8 `query` <=512 bytes and integral `maxFiles` 1–12 (default 4), and inject native `projectPath` from trusted physical access. Limit native result to 256 KiB, each call to 30 seconds, and one session to 10 calls/2 minutes; trusted configuration may lower but model input cannot raise those caps. Bind the finite session to the exact approval tuple; reverify current authority before native work and before releasing buffered source/location. Keep CodeGraph counters independent of 18.1 file-tool counters under the same source authority. **Rationale**: The [raw schema](evidence/native-mcp-standalone-01.raw.json) exposes model-supplied `projectPath`; [AD-6/15](../../docs/bmad/planning-artifacts/architecture/ARCHITECTURE-SPINE.md), [O-NFR01/O-AR09](../../docs/bmad/planning-artifacts/october-release-epics.md) and [spec FR-002–FR-009](spec.md) require application binding, cancellation and truthful readiness. Existing CodeGraph process bounds inform the proposed response/call limits. **Alternatives**: unfiltered native tool, model-selected root, shared mutable project session or silent source-only fallback violate authority/truthfulness. **Open verification**: host qualification must confirm these proposed caps preserve useful behavior; any same-binding sharing needs a separate concurrency proof.

## Decision 4: In-place index placement, startup and process authority

**Pinned findings**: Installed `@colbymchenry/codegraph`/`codegraph-win32-x64` 1.5.0 `directory.js` permits `CODEGRAPH_DIR` only as a plain name and joins it to the project root. `createDirectory` writes `.codegraph/.gitignore` and the DB beneath that root. CLI `init` calls SDK `init(index:false)` and `indexAll`, then can offer project-root `codegraph.json` and Git-hook writes; it records usage telemetry. SDK `CodeGraph.init/open` bypass CLI offers but helper resolution and all index writes need qualification. `serve --mcp -p ... --no-watch` disables watching, but MCP startup can write index state, and the default can start a detached shared daemon/log/lock. Pinned MCP source supports `CODEGRAPH_NO_DAEMON=1` direct mode and starts telemetry/update checking unless disabled. Local inspected files include `directory.js` SHA-256 `F164E53DB714519B45516A97164D709647110DBE1F15C6C655EDD6DAB2BF02BA`, `utils.js` SHA-256 `CE085743930D231F92C842DA021416581680775B1C41C1371E218A71ADA82461`; [startup inspection](evidence/codegraph-startup-inspection-01.json) pins `bin/codegraph.js`, `installer/index.js` and `index.js`. The [upstream external-index request](https://github.com/colbymchenry/codegraph/issues/986) is not an installed capability.

**Direct-process risk and pre-existing state**: Story 18.2's owner-issued capability still separately names trusted coordinator creation/removal of the one `.codegraph` root entry and descendant writes; a descendant-only grant cannot create it. The coordinator rejects foreign/prior state, creates an empty owned entry under that application grant and keeps one index owner through workspace/batch lifetime. This grant does not confine the directly launched CodeGraph child at the OS level. The user declined AppContainer/profile and a checked-in Windows-specific fixture harness, choosing the pinned process as a trusted dependency with inherited host rights. Before launch, verify the 1.5.0 installation/bundle and set `CODEGRAPH_NO_DAEMON=1`, `CODEGRAPH_NO_WATCH=1`, `DO_NOT_TRACK=1`, `CODEGRAPH_TELEMETRY=0`, `CODEGRAPH_NO_UPDATE_CHECK=1`, `CODEGRAPH_NO_DOWNLOAD=1`; close CLI stdin. The observed direct Git/no-Git fixtures each added four files under `.codegraph` only, did not change local source/root config/hooks, returned native results, and exited the four launched parent PIDs. A hook-sync offer appeared on both fixtures despite no-watch and was declined by closed stdin. External filesystem writes, network attempts/outbound denial, descendant process cleanup and generic production behavior were not observed or proved. FR-010 still requires unchanged prepared source/config/hooks; any observed deviation fails app-bound qualification and returns for authority. No repository-wide hashing or automatic monitor is proposed. ## Decision 5: Positive owned-state reader repair and contained native excerpts

**Decision**: Story 18.3 changes only existing Infrastructure prepared-source reader internals for a tool-state directory positively bound by Story 18.2 to the exact approved Repository/root/lifetime. On list/search it omits that state before eligible-source page formation and accounts for limits truthfully; on direct ranged read it denies the bound subtree. Continuations retain/revalidate the ownership and observed directory identities; a change returns `ChangedInput` or denial rather than a silent skip/duplicate. An unbound same-named `.codegraph` directory follows ordinary Story 18.1 source behavior. Preserve the public `list_prepared_source`, `read_prepared_source`, `search_prepared_source` signatures, direct ranged-read semantics and existing budgets. **Rationale**: [Current spec FR-012/SC-009](spec.md) and the [owner invalidation](evidence/source-reader-owner-invalidation-01.json) assign this bounded consumer repair to 18.3; the [read context](../../src/dotnet/Vulgata.Infrastructure/Source/PreparedSourceReadContext.cs) already owns handle-relative traversal, pagination and `ChangedInput` behavior. No separate descriptor/filter contract or name-only suppression is justified. **Native result seam**: [DR-18-3-01](evidence/definition-review-02.raw.json) records that the current fixture [native client](../../src/dotnet/Vulgata.Infrastructure/Analysis/CodeGraph/NativeCodeGraphMcpClient.cs) uses lexical/path reopens (`File.Exists`, `FileInfo`, `File.GetAttributes`, `File.ReadAllText`). Production replaces/binds this verifier to the 18.2 contained physical-read capability: canonical relative path only, handle-relative held read, bounded excerpt comparison, result-time live authority, denial/limitation on reparse/race/changed input. Controlled fixture success remains valid only for its old boundary. **Open dependency**: 18.2's actual positive binding and contained-read fields, lifetime and file/type integration must be agreed and verified before app-bound execution; this research does not invent a shared API.

## Authority and compatibility

The [Constitution](../../.specify/memory/constitution.md) places tool/process adaptation in Infrastructure and bounded agent execution behind injected contracts. [October proposal item 11](../../docs/bmad/planning-artifacts/sprint-change-proposal-2026-09-26-october-batch-release.md) selects direct host execution. In-place `.codegraph` state beside unchanged prepared source can satisfy [AD-3/4/6](../../docs/bmad/planning-artifacts/architecture/ARCHITECTURE-SPINE.md) if owner-issued write/contained-read/positive-binding authority, bounded reader repair and truthful app-bound source behavior are verified. The direct process does not provide OS preventive containment; it carries residual external-write/network risk despite local-only flags, and no generic no-side-effect claim follows from two fixtures. Completed independent client/wrapper work remains valid; dependent work awaits checkpoint, affected review and host qualification. The [callable-seam lesson](../../docs/project-lessons.md) protects the public seam; the [launcher lesson](../../docs/project-lessons.md) keeps restricted sandbox denial separate from product failure. No database migration, generic MCP registry, JDT-LS work, provider call, copy, Git acquisition or automatic monitoring is planned. Historical CLI/JSON contracts remain their scope.
