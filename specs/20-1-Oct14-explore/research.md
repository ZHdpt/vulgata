# OCT-EXPLORE research and decisions

Date: 2026-10-06. Source inspection only; no runtime qualification. Direct SpecKit Phase 0. No unresolved product choices require speckit-clarify.

| Decision | Evidence and rationale | Alternatives evaluated |
| --- | --- | --- |
| Reader before graph | October lane brief explicitly requires ordinary IT CL reading before BL/Chat/graph completion. | Waiting for broad batch or complete original stories would expand scope and delay usable output. |
| Depend on B0 exact read contract | `Core/DomainServices/IKnowledgeStoreRepository.cs` has only logical-ID `GetCurrentAsync`; `Infrastructure/Data/KnowledgeStoreRepository.cs` selects `CurrentVersionId`. Existing `RepositoryAccessScope` permits an absent live verifier and lacks publication/mode/purpose semantics. | A wrapper around current reads cannot prove exact membership or live all-contributor authorization. No direct producer query or consumer policy fork. |
| Ordinary authenticated routes with Knowledge policy | Existing Management/DocumentsPage and GraphPage both require ManagementAccess. AD-29 and PRD FR-12.6 require ordinary Knowledge authorization. | Relaxing the management shell would change unrelated authorization; new feature routes avoid that. Integration owns navigation and legacy-route disposition. |
| Native SVG plus accessible list | Web package file has no graph library. Only 40 nodes/80 Edges and basic movement are selected. | A new library/package, graph store or framework adds shared coordination without required first-deliverable value. Advanced layout remains deferred. |
| Structured encoded rendering | Existing `KnowledgeDocumentTypes.cs` provides canonical content/section patterns, but B0 owns the final safe read representation. Razor encoding preserves text without executing generated HTML. | Raw Markdown-to-HTML/MarkupString risks active content; installing a rendering package is unnecessary for the first structured reader. Rich formatting can be considered later without dropping readable content now. |
| F3: one visible exact-content chunk with explicit next | Named Business contract Consumer reads limits responses to 64 KiB UTF-8 and supplies protected exact section/chunk continuation. Preserve that owner protocol, ordering, exact identity and visible qualifications; recheck authority per response. | A one-response Document assumption silently truncates valid content. Automatic drain or retained-chunk accumulation adds unbounded UI state and revalidation complexity; replacing one chunk per explicit action gives complete traversal without a new pagination framework. |
| Web facade with presentation-only ViewModels | Web already references Core/Shared/ViewModels; ViewModels currently references Shared only and has no implementation files. | Adding Core or Infrastructure references to ViewModels is unnecessary. Shared presentation ports wrap owner-approved handles without defining new Knowledge identities. |
| Explicit bounded one-hop graph | Accepted relationships and safe seeds come from one Knowledge Read Context. No recursive expansion is requested. | Corpus-wide load then filter risks unbounded work and metadata leaks; CodeGraph symbol edges and similarity are not Knowledge Edges. |
| Clear old state while refreshing | Live authorization and asynchronous mode/selection changes make stale results dangerous. Request generation plus cancellation prevents obsolete results from applying. | Keeping cached content visible through denied refresh or using cancellation alone does not protect disclosure. No new visibility-epoch infrastructure is needed. |
| Preserve broader history/source obligations | Brief narrows first delivery; PRD FR-9.4, FR-11.2/11.7, FR-12.6 and AD-29 retain broader history/source requirements. | Declaring them removed or completed would require a PRD change; explicit unfinished scope needs neither invented functionality nor a new waiver. |

Independent read-only research was performed by `research_read_boundary`. It confirmed the current-version limitation, optional-verifier risk, package baseline, ordinary-route need and shared Web ownership. Its findings informed this design; it did not author implementation or claim passing runtime tests.

Applicable authority: delivery/integration/reader-graph briefs, constitution 2.0.0, architecture gateway and AD-24/25/29, glossary, PRD FR-9.4, FR-11.1–11.4/11.7 and FR-12.6, testing guidance. `CONTEXT-MAP.md` and `docs/adr/` are absent; domain guidance explicitly directs this repository to the gateway/spine instead. No scaffolding or external research was necessary.
